# Focusday v1.5 제품 명세

## 목적과 범위

생각난 일을 빠르게 담고 오늘 실행할 일만 고르는, 계정 없는 개인용 로컬 앱. 주 사용자는 관리 체계·설정을 오래 유지하고 싶지 않은 개인이라는 **설계 가설**이다.

React + TypeScript + Vite + CSS + localStorage. 최상위 탐색은 오늘/전체. 로그인, 서버, DB, 클라우드 동기화, 협업·공유, 캘린더, 시간별 일정, 반복·알림, 하위 작업, 메모·첨부, 습관, 포모도로, 게임화, 앱 내부 AI, 음성·자유형 자연어 이해, 드래그, 대량 편집, 테마·다크 모드, PWA는 제외한다.

v1.3은 노션 작업 화면을 참고한 밝은 워크스페이스다. 232px 사이드바, 흰 작업 페이지, 얇은 목록 구분선, 정렬된 속성과 공통 패널/sheet를 사용한다. 검색 진입과 데스크톱 직접 백업은 실제 기존 동작에 연결한다. 기능·데이터 의미는 유지한다. [DESIGN.md](../DESIGN.md) · [전후 화면·검수](V1_3_UI_REDESIGN.md).

## v1.5 자동화

자동 계획은 새 방문에서 켜져 있으며 1/3/5개(기본 3개)를 고른다. 첫 미완료 목록에서 오늘 계획의 id를 정한다. 완료·삭제·무기한/미래 항목 추가·새로고침으로 빈자리를 채우지 않는다. 새로 입력한 오늘 기한·지난 기한은 사용자가 명시한 일정으로 취급해 상한과 관계없이 오늘 계획에 추가한다. 따라서 기존 3개에 오늘 기한 1개를 담으면 4개가 되며, 이 동작은 미리보기와 저장 알림에서 안내한다. 직접 오늘에 넣기, 분량 변경, 하나 더 하기도 계획을 바꾸는 동작이다. 분량을 줄여도 이미 완료한 항목은 유지한다. 자동 계획 계산은 Task와 기한을 수정하지 않는다.

종료 안내는 계획한 항목이 모두 완료되고, 전체 미완료 중 오늘/지난 기한도 남아 있지 않을 때만 표시한다. 이전 저장본이나 수동 제외로 오늘 기한이 계획 밖에 남았으면 ‘오늘까지 할 일이 남아 있어요’를 표시하고 ‘남은 일 오늘에 넣기’로 연결한다. 이 버튼은 해당 기한 항목만 추가하며 미래 일은 넣지 않는다. 원래 제외한 항목을 사용자 선택 없이 자동으로 다시 넣지는 않는다.

후보 순서: 기한 초과 → 오늘 기한 → 직접 선택 → 과거 어느 날이든 선택한 미완료 → 높은 우선순위 → 가까운 미래 기한 → 나머지. 같은 그룹은 기한(초과/미래 그룹), 높은 우선순위, 생성 시각, id로 안정적으로 정렬한다. 자동 모드를 끄면 아래 기존 수동 규칙을 사용한다.

`지금 할 일`은 현재 계획의 미완료 항목을 위 후보 순서로 정렬하고, 미루지 않은 첫 항목을 보여준다. 새로 입력한 오늘 기한은 기존 미래·무기한보다 앞선다. 완료하면 다음 항목으로 이동한다. ‘나중에 하기’는 오늘 순서에서만 건너뛰고 원본·기한·완료를 바꾸지 않는다. 모두 미루면 ‘미뤄 둔 일 이어가기’를 제공한다. 날짜가 바뀌면 오늘 계획과 건너뛰기 기록을 비우고 다시 고른다. 이전 버전에서 시작한 항목 id는 마이그레이션 시 우선 보존한다.

메모 정리는 줄바꿈·문장 구분과 지원하는 연결 표현으로 항목을 나눈다. 오늘·내일·모레·글피, 이번/다음/다다음 주 요일, 명시 날짜, N일 뒤/후, 주말을 달력 날짜로 바꾼다. 분류는 키워드, 우선순위는 명시 태그나 강한 표현으로 제안한다. 임의 자연어를 이해하는 AI는 아니다. 날짜 충돌·유효하지 않은 날짜는 전체 저장을 보류한다. 반복·시간 알림은 만들지 않고 미지원 표현은 제목과 경고에 남긴다. 최대 100개씩 처리한다.

‘제출하고’, ‘정리하고’, ‘돌리고’ 등 명시한 행동 연결을 분리한다. 같은 문장 첫머리의 날짜를 뒤 항목에 적용하면 확인 안내를 표시한다. 뒤 항목의 명시적 날짜를 우선하며 다음 문장·줄에는 앞 날짜를 옮기지 않는다. ‘친구하고’, ‘공부하고 싶은’ 같은 표현은 분리하지 않는다. 반복 요청은 날짜를 임의 기한으로 바꾸지 않고 제목에 보존한다. 반복 맥락을 유지하려고 해당 문장의 행동 연결도 추가 분리하지 않는다.

자동 정리의 Enter는 미리보기를 열고, 제목·기한·분류·우선순위 수정 또는 항목 제외 후 담기로 확정한다. 인식을 끄면 한 줄씩 원문 그대로 바로 담는다. Shift+Enter는 줄바꿈이며 IME 조합 중/종료 직후 제출을 막는다. 같은 제목을 허용하고 고유 id를 발급한다.

미리보기의 제목·분류 입력도 IME 조합 중/종료 직후 Enter로 저장하지 않는다. 미리보기를 만든 날짜와 현재 날짜가 달라지면 인식한 기한과 수동 수정 내용을 유지하며, 새 날짜마다 ‘정리한 기한을 확인했어요’를 선택해야 저장할 수 있다. Enter로도 이 확인을 우회하지 않는다. ‘메모로 돌아가기’ 후 다시 정리하면 현재 날짜로 원문을 해석한다.

원문이 있으면 ‘예시 덧붙이기’로 표시하고 줄바꿈 뒤 예시를 붙인다. 24,000자 입력 제한을 넘는 경우는 원문을 유지하고 안내한다. 첫 계획을 만들기 전의 저장 안내와 기존 계획이 있는 경우의 분량 유지 안내를 구분한다.

자동 모드의 새 항목은 전체 목록에 담으며 기본 focusDate=null이다. 최초 비어 있던 목록에서는 오늘 계획을 만들고 입력한 오늘/지난 기한을 모두 포함한다. 기존 계획에는 새 항목 중 dueDate≤오늘인 항목만 자동 추가한다. ‘모두 오늘 할 일에 넣기’를 선택하면 미래·무기한을 포함해 묶음 전체를 추가하고 focusDate도 오늘로 지정한다. 수동 모드에서는 오늘 화면의 입력은 오늘 선택, 전체 화면은 null이다. 자동 모드의 오늘에 넣기/빼기는 실제 계획 id와 일치하며 편집 창도 같은 상태를 표시한다. 일괄 추가를 되돌리면 새 항목과 함께 이전 계획도 복구한다.

자동화 설정은 키 `focusday:auto:v1`을 유지하며 내부 version2다. enabled, limit, day, currentTaskId, skippedTaskIds, planTaskIds를 저장한다. 유효한 version1은 읽을 때 변환하며 손상 시 자동 덮어쓰기를 막는다. 새 계획을 만들 때 저장하고, 쓰기 실패는 메모리 적용·지속 경고·재시도를 제공한다. Task·문구 형식은 유지한다. 백업은 Task 전용이며 복원 성공 뒤 복원된 목록으로 계획을 다시 만든다.

## 데이터

v1.4에서 추가한 오늘의 한 문장, 완료 순간의 격려, 오늘의 성취 기록을 유지한다. 자세한 단일 기준은 [v1.4 의미/저장/실제 동작](V1_4_FINAL_UPDATE.md)이다. 문구 설정은 앱 정보의 단일 panel에서 초안 저장/취소로 관리한다.

성취는 현재 비예시 Task의 completedAt을 로컬 날짜로 변환해 오늘인 항목이며 최근 완료/id순, 검색과 무관하다. 현재 목록 기준이므로 완료 취소·삭제·복원에 따라 바뀐다. 격려는 직접 완료0→1/2→3에만 날짜별 한 번, 꺼진 동안도 처리한다. 초기에 로드하거나 파일 복원·undo로 증가한 수는 격려를 만들지 않는다.

UI 설정/내 문장/두 시점 표지는 별도 `focusday:ui:v1` / UI version1에 저장하며 전체 할 일 백업에서 제외한다. 기본 calm/on, trim1–120 Unicode code point, plain text. 손상 설정은 자동 덮어쓰지 않고 재읽기/명시적 설정 초기화를 제공한다. 저장 실패는 초안을 유지하며 task 저장 상태와 분리한다. 표지 실패 시 세션 중복 방지만 보장한다.

`AppData = { version: 1, tasks: Task[] }`, 저장 키 `focusday:v1`.

| 필드                  | 규칙                                                       |
| --------------------- | ---------------------------------------------------------- |
| id                    | 고유 문자열. 새 항목은 crypto.randomUUID                   |
| title                 | trim, 필수, 최대 200자(입력과 JavaScript 문자열 길이 기준) |
| createdAt / updatedAt | ISO UTC timestamp                                          |
| completedAt           | ISO UTC timestamp 또는 null                                |
| dueDate / focusDate   | 유효한 로컬 달력 날짜 YYYY-MM-DD 또는 null                 |
| priority              | none / low / medium / high → 없음 / 낮음 / 보통 / 높음     |
| category              | 단일 선택적 문자열, trim 후 최대 24자 또는 null            |
| isDemo                | boolean, 직접 만든 항목은 항상 false                       |

## 생성·보기·검색

자동/수동 모드의 생성 기본값은 위 v1.5 규칙을 따른다. 인식하거나 직접 고른 속성만 채우며 기본 dueDate=null, priority=none, category=null, completedAt=null이다. 저장 후 입력을 비우고 포커스를 돌린다. 공백만 입력하면 오류를 안내한다. IME 조합 중 Enter, keyCode 229와 조합 종료 직후 같은 Enter는 제출하지 않는다.

수동 모드 오늘의 미완료 포함 조건은 `focusDate === today || (유효한 dueDate !== null && dueDate <= today)`이다. 기한 초과는 별도 섹션에 먼저 표시하고 나머지 오늘 항목과 중복시키지 않는다. 전체에는 모든 미완료가 있다. 완료는 전체의 접을 수 있는 영역에 제공한다.

검색은 현재 보기의 제목·분류에서 대소문자를 구분하지 않는 부분 문자열 검색이다. 전체에서는 완료도 포함하고 검색 중 완료 영역을 펼친다. 탐색 메뉴 수는 검색과 무관한 미완료 수, 검색 결과 수는 현재 보기의 검색 일치 수다.

## 수동 모드와 전체 정렬

- 오늘 기한 초과: 오래 지난 기한 → 높은 우선순위 → 먼저 생성 → id.
- 오늘 나머지: 높은 우선순위 → 먼저 생성 → id.
- 전체: 오늘/기한 초과 → 미래 기한 → 나머지. 각 그룹 안은 높은 우선순위 → 먼저 생성 → id.
- 완료: 최근 완료 → id. id는 동률의 안정적인 기준이다.

## 오늘 선택과 기한

‘오늘에 넣기/빼기’는 focusDate를 변경하고 updatedAt을 갱신한다. 자동 모드에서는 실제 계획 id도 함께 바꾼다. id·기한·그 밖의 속성은 유지한다. 수동 모드에서는 기한이 오늘/과거이면 직접 선택을 해제해도 오늘에 남으며 이유와 기한 편집 버튼을 제공한다. 자동 모드에서는 계획에서 빠지고 급한 일 안내에 포함될 수 있다.

getFullYear/getMonth/getDate로 오늘을 구한다. 날짜 더하기는 로컬 달력의 setDate로 처리하며 시간은 정오로 설정한다. 날짜 간 차이는 달력 성분으로 계산해 DST의 23/25시간과 분리한다. 자정 타이머, window focus, visibilitychange에서 오늘과 다음 자정 타이머를 갱신한다. 지난 focusDate는 수동 오늘에서 빠지지만 전체의 항목은 삭제하지 않는다. 자동 모드에서는 이전에 고른 미완료 후보로 다시 추천될 수 있다.

## 편집·완료·복구

동일 편집기가 데스크톱 우측 모달 drawer, 모바일 bottom sheet로 열린다. 제목·오늘 집중·기한 설정/해제·오늘/내일/일주일 뒤 빠른 날짜·우선순위·분류·보조 삭제를 제공한다. 저장만 적용하며 취소/Escape는 초안을 버린다. 빈 제목과 잘못된 날짜는 저장을 막는다.

자동 모드에서 기한을 다른 값에서 오늘/지난 날짜로 바꾸면 ‘오늘에 포함’을 함께 선택한다. 사용자가 이어서 직접 해제할 수 있으며, 이미 오늘 기한인 항목의 제목만 고치는 경우는 기존 제외를 뒤집지 않는다. 날짜가 바뀌면 편집창의 오늘 선택은 새 날짜의 실제 계획으로 갱신하고, 제목·기한 등 작성 중 초안은 보존한다. 수동 모드의 지난 focusDate를 새 날짜로 임의 이동하지 않는다.

native dialog와 명시적인 Tab 경계 유지, 최초 제목 포커스, 닫힌 후 호출 지점으로 복귀를 제공한다. 행이 사라지면 인접 항목 또는 입력창으로 포커스를 옮긴다. 모바일 편집기는 visualViewport 크기 변경을 반영한다.

완료는 completedAt을 기록하며 전체 완료 영역에서 복원할 수 있다. 완료·삭제·일괄 추가·편집·오늘 선택·순서 미루기·분량/모드 변경의 최근 한 건을 되돌린다. 해당 변경과 같은 날짜의 자동 계획을 함께 복구한다. 삭제는 원래 Task 전체, 완료는 해당 항목의 완료 여부, 추가는 그 묶음만 복원한다. 추가를 되돌릴 때 입력창이 비어 있으면 원문을 돌려준다.

알림은 기본 8초이며 hover·키보드 포커스 동안 만료를 멈춘다. 알림이 사라져도 상단 최근 작업 버튼은 다음 변경·새로고침 전까지 남는다. 전체 기록을 순서대로 복구하는 기능은 아니다. 백업 복원·예시 일괄 제거는 이 기록을 비우며 되돌리기 대상이 아니다. 날짜가 바뀌면 순서·분량·모드 등 계획 변경만의 undo와 해당 알림을 지우고 이유를 안내한다. 완료·삭제·추가·편집 undo는 유지하되 새 날짜의 계획을 덮어쓰지 않는다. 되돌린 오늘/지난 기한이 새 계획 밖에 생기면 기존 기한 안내와 종료 방지가 적용된다.

## 저장·복구 상태

- Task·문구의 초기 load는 읽기만 수행한다. 빈 목록의 기본값을 자동 저장하지 않는다. 자동 계획은 유효한 미완료 목록에서 처음 만든 계획을 별도 저장한다.
- 접근/읽기 실패: 자동 쓰기 차단, 다시 읽기. 성공 시 기존 항목과 메모리 항목을 id로 합친다.
- JSON/스키마/버전 오류: 원본 보존, 다운로드, 별도 명시적 초기화 확인.
- 쓰기 실패: 메모리 변경은 유지, 지속 경고·저장 재시도. 실제 다음 쓰기 성공 때만 실패 상태를 해제한다.
- 저장됨은 setItem 성공 후에만 표시한다. 초기 정상 데이터 읽기는 ‘로컬 데이터 불러옴’으로 표시한다.
- 초기화는 손상 원본을 현재 탭 목록으로 교체한다. setItem 실패 시 원본을 유지한다.

## 선택형 예시·빈 상태

`?demo=1` 또는 예시로 둘러보기로 별도 체험에 진입한다. 오늘 기준 예시 5개와 독립된 메모리 저장소를 사용한다. Task·문구 설정·자동화 설정 모두 실제 localStorage를 읽거나 쓰지 않는다. 완료/편집/입력/백업/복원도 체험 안에서 동작한다. 새로고침/처음부터 체험은 예시로 초기화하고 내 할 일 사용하기는 원래 개인 저장소로 돌아간다. 체험 백업 파일 이름에는 demo를 표시한다.

체험 화면은 예시의 성취·격려도 보여준다. 개인 모드의 예전 isDemo 항목은 기존처럼 성취에서 제외하며 메뉴에서 예시만 제거할 수 있다. 개인 기록과 예시를 합치는 이전 진입 방식은 사용하지 않는다.

첫 빈 화면, 오늘만 빈 화면, 전체 미완료 없음, 검색 결과 없음, 읽기/쓰기 오류를 별도로 안내한다. 검색 지우기, 첫 입력, 전체 보기, 예시, 재시도 등 다음 행동을 제공한다.

## 접근성과 시각 기준

semantic HTML, 이름 있는 native 입력/버튼/체크박스, 명확한 focus ring, status/alert, 텍스트로 기한·우선순위, reduced-motion을 사용한다. 핵심 터치 영역은 44px 이상을 목표로 한다. N 새 입력, / 검색은 일반 입력·IME·조합키·편집/확인 모달에서 가로채지 않는다. 일반 텍스트 대비와 실제 검증 범위는 [검증 기록](validation.md)에 있다. 전체 WCAG 준수 판정은 하지 않았다.

## 오늘 계획하기와 어제 이어가기

최상위 탐색은 오늘/전체 두 개를 유지한다. 오늘 계획하기는 오늘 화면의 보조 행동으로 열리는 단일 native dialog다. 데스크톱은 drawer, 모바일은 bottom sheet이며 기존 편집기·데이터 관리와 중첩되지 않는다.

미완료만 후보로 제시하고 기한 초과 → 오늘 기한 → 로컬 달력의 어제 focusDate → 높은 우선순위 순서로 한 번만 배치한다. 여러 조건을 만족하면 상위 그룹에 배치하고 충족한 사실 이유를 모두 보여준다. 기한 초과 안은 오래 지난 기한 → 기존 우선순위/생성/id 순서, 나머지 그룹은 기존 우선순위/생성/id 순서다. 이미 오늘 집중인 후보는 집중 중 상태를 보여준다.

항목별 집중하기/집중 해제는 기존 저장·오류 처리로 즉시 적용한다. 별도 일괄 선택·개수 제한·AI 추천은 없다. 후보가 없으면 빈 상태와 전체 보기 경로를 제공한다. 선택 후 후보 조건을 벗어나는 어제 항목은 후보에서 빠지고 오늘 목록에 표시된다. 선택 피드백을 제공하고 사라진 버튼의 포커스는 패널 닫기로 이동한다.

어제 안내 수는 `completedAt === null && focusDate === addDays(today, -1)`이다. 기한으로 이미 오늘에 표시되는 항목도 count에 포함할 수 있지만 복제하거나 목록에 두 번 표시하지 않는다. 완료·이틀 이상 지난 집중은 어제에서 제외한다. 자동 이월·자동 팝업은 없다. 자정·focus·visibilitychange에서 안내·후보·요약을 함께 계산한다.

오늘 요약은 미완료 중 focusDate=오늘의 직접 집중 수와, 유효한 dueDate≤오늘이며 focusDate≠오늘인 기한 표시 수다. 두 집합은 겹치지 않고 합계는 검색 전 오늘 미완료 수와 같다.

## JSON 백업·복원

예시 및 앱 정보 메뉴에서 보조 패널을 연다. 전체 현재 메모리 목록을 `format: "focusday-backup"`, `formatVersion:1`, `exportedAt: ISO UTC`, `data:{version:1,tasks:[]}`로 다운로드한다. 파일명은 `focusday-backup-로컬날짜.json`이다. 완료·예시·모든 속성을 포함하고, 쓰기 실패 중의 아직 저장하지 못한 변경도 포함한다. 저장 보호 중에는 현재 탭 목록만 포함하고 원본은 포함하지 않음을 알린다. 내보내기는 저장을 호출하지 않으며 Object URL을 해제한다.

파일 최대 크기는 10MiB다. JSON·정식 format/version·exportedAt·기존 저장 스키마·모든 필드/길이/달력 날짜/timestamp/id 중복을 동일 validator로 확인한다. 파일 선택·취소·검증 실패는 앱 데이터와 저장 상태를 바꾸지 않는다. 유효하면 전체/미완료/완료 수와 방식 미리보기를 표시하고 해당 제목으로 포커스/스크롤을 옮긴다. 늦은 파일 읽기는 다음 선택과 닫힌 패널을 변경하지 않는다. raw 원본 다운로드를 정식 백업으로 취급하지 않는다.

기본 합치기는 현재 항목을 모두 유지하고 백업의 새 id만 추가한다. 중복 id와 내용이 다른 중복 수를 별도로 보여주며 현재 항목을 유지한다. 같은 제목이어도 다른 id는 별도 항목이다. 전체 교체는 현재/복원 개수 → 같은 패널의 확인 단계 → 명시적 교체 버튼을 거치며 교체 전 백업과 취소를 제공한다.

완성된 결과를 한 번의 saveData 호출로 저장한다. 성공한 뒤에만 메모리/목록을 바꾸고 완료를 표시한다. 실패하면 기존 메모리·저장 원본·전역 저장 상태를 유지하고 패널에 복원 오류·재시도·취소를 제공한다. blocked/unavailable은 복원으로 우회하지 않는다. 성공 후 이전 실행 취소·편집·검색을 정리하고 보기·후보·개수를 새 데이터로 계산한다.

앱 버전은 1.5.0이지만 할 일 저장 형식은 v1.0과 동일하다. 로그인·서버·자동 백업·동기화는 없다. 파일은 사용자가 직접 보관하는 사본이다. 백업은 데스크톱 사이드바에서도 직접 열며, 모바일은 기존 앱 메뉴에서 연다. 복원 실패 시 오류에 초점/스크롤을 옮기고 적용 전 데이터는 유지한다.

## v1.2 입력·백업 보완

상세 편집에서도 composition 이벤트 중, native isComposing/keyCode229, 조합 종료 직후 80ms의 Enter를 제출로 처리하지 않는다. textarea의 일반 Enter는 줄바꿈이고, 유효한 분류 입력 Enter와 저장 버튼 활성화는 저장한다. 실제 OS IME 검증과 구분한다.

백업은 전체 데이터를 compact JSON으로 직렬화한 후 UTF-8 byte를 검사한다. 10MiB 이내만 정식 백업으로 다운로드하고 크기도 안내한다. 초과하면 이유를 표시하고 다운로드를 중단한다. 목록·원본은 유지하며 부분 항목 제외나 분할은 하지 않는다. 기존 padded JSON 파일과 formatVersion1은 지원한다. 지원 범위를 넘는 미저장 메모리 전체 데이터의 파일 보존은 보장하지 않는다.
