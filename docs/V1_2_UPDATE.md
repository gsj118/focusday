# Focusday v1.2.0 업데이트 기록

이 평가는 AI가 구성한 가상 사용자 관점과 실제 앱 조작/자동화 검증을 결합한 Synthetic Beta다. 실제 사용자 모집·인터뷰·만족도·사용자 과업 시간 측정은 수행하지 않았다.

시작 main `7ff35e7` / 앱 1.1.0, 기존 출시 태그 `v1.1.0`은 `e29397e`다. 두 revision의 앱 소스는 같았다. [v1.1 기준 문서·화면·증거](versions/v1.1.0/index.md)를 보존하고 앱과 package만 1.2.0으로 올렸다. `focusday:v1`, 데이터 `version:1`, 모든 Task 필드와 기존 저장 보호는 유지한다. 사용자의 실제 목록이나 브라우저 프로필은 테스트에 사용하지 않았다.

## 행동 변화와 유지한 규칙

- 백업: 전체 다운로드→미리보기→합치기/교체 흐름은 같다. 들여쓰기를 제거했고 성공 안내에 크기를 보여준다. 기존 정식 wrapper/formatVersion과 v1.1 파일은 유지한다.
- 10MiB를 넘는 **현재 메모리 전체 데이터**는 백업 다운로드를 중단하고 이유를 표시한다. 항목 자르기·완료/예시 제외·부분 파일·무제한 가져오기는 없다. 모든 데이터 크기의 round trip을 해결했다고 주장하지 않는다. 지원하는 범위는 compact 정식 파일 최대 10MiB이며, 한도를 넘는 미저장 메모리 데이터의 파일 보존 경로는 이번 범위 밖이다.
- 7000개의 긴 한글 항목처럼 기존 5MiB를 넘는 compact 백업도 전체 속성 round trip을 검사했다. UTF-8 정확히 10MiB는 허용하고 1byte 초과는 거부한다. 20000개 합성 메모리의 초과 내보내기는 다운로드 0·원본 유지로 검사했다. 대량 데이터 경계는 정상 목록 사용성 결과가 아니다.
- Enter: 빠른 제목 입력은 추가, 상세 textarea는 줄바꿈, 조합 중/확정 직후 Enter는 저장 방지, 유효한 분류 입력 Enter와 저장 버튼 Enter/Space는 정상 저장이다. 모든 Enter를 일괄 저장으로 바꾸지 않았다.
- 기한·집중 분리, 수동 어제 이어가기, 사실 후보, 제목/분류 검색, 완료/삭제 undo, 선택형 예시, 저장 성공 후 복원 적용은 그대로다. 동일 제목의 서로 다른 id도 허용한다.

## 평가 도구 문제와 제품 실패의 구분

초기 레이블/selector 범위와 undo updatedAt 기대를 스크립트에서 보완했다. 타입 검사의 미사용 import는 수정했고, 새 build 전에 시작한 옛 build 검사는 취소해 v1.2 근거에서 제외했다. 첫 최종 실행의 native date sanitation 후 disabled 해제를 누르려던 검사도 도구 기대 오류였다. [첫 70 PASS/1 도구 실패](evidence/v1.2/root-first.json)를 보존하고 정상 정책에 맞춰 최종 전체 71 PASS를 확인했다. 데이터를 검증하는 기존 기대는 완화하지 않았다.

## 한계와 사람이 확인하면 좋은 과업

1. 실제 휴대폰에서 가상 키보드 Enter/완료와 시트 스크롤/safe-area 확인. 현재 touch·390×480은 에뮬레이션이다.
2. 실제 한글 OS IME로 빠른 입력과 상세 분류/제목의 조합 확정 Enter 확인. 현재는 composition 이벤트와 실제 automation 키를 결합했다.
3. 처음 사용하는 사람의 제목 편집 발견·검색 중 계획 선택 해석 확인. 두 항목은 AI walkthrough 가설이며 시간/성공률을 측정하지 않았다.

Safari/Firefox·native 브라우저 확대·스크린 리더·전체 WCAG·전체 보안 감사·사용자 연구는 미실행이다. 200%는 CSS reflow 동등 조건으로 범위를 명시했다. 앱은 서버 백업·자동 동기화·다중 탭 동시 편집을 제공하지 않는다.
