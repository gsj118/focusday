# AI 활용 과정과 실제 결과

이 과제는 AI 활용을 제품 안의 기능이 아니라 **제작 과정**으로 보여준다. 같은 Codex 세션이 자료를 해석하고 구현·자체 검토·도구 실행·수정·문서화를 수행했다. 별도 모델, subagent 또는 사람 검토는 수행하지 않았다. 브라우저와 테스트 도구에서 나온 결과를 AI 판단과 구분한다.

## 실제 요청

- [최초 제작 지시](ai-prompts/01-implementation.md): 사용자가 실행을 명시적으로 요청한 첨부 명세. 원본 그대로 보존.
- [현재 사용자 실행 요청](ai-prompts/00-user-request.md): 현재 폴더 개발·검증·README 순서·커밋·조건부 push 요구.
- [공개 저장소 생성 후속 요청](ai-prompts/03-publication-request.md): 저장소 선택을 맡긴 후 실제 계정 확인·생성·push·Pages 배포·공개 주소 검증.
- [자체 검토 기록](ai-prompts/02-review-notes.md): 별도 대화가 있었던 것처럼 만든 프롬프트가 아니라, 이 세션에서 실제 수행한 검토와 결과.

## 연결 과정

| 단계                | AI의 작업                                                  | 실제 근거·결과                                                                 |
| ------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 자료 해석           | 리서치의 관찰과 가설 분리, 최종 제작 명세 우선             | 원문·제작 요청 SHA-256 일치 확인, research.md / decisions.md                   |
| 설계                | 오늘 집중과 기한 분리, 점진적 속성 편집, 저장 보호         | domain.ts / storage.ts / 제품 명세                                             |
| 구현                | domain·어댑터·컴포넌트·CSS와 테스트 작성                   | 현재 소스와 실제 작업별 Git 커밋                                               |
| 저장·날짜·복구 검토 | 초기 덮어쓰기 차단, 읽기·쓰기 오류, 타이머 격리, 날짜 경계 | 단위 테스트 25개, 서울·뉴욕 timezone 테스트, 브라우저 오류 주입·제어 시계 검증 |

| 접근성 검토         | 키보드·포커스·Tab 경계·대비·이름                           | 포커스 복귀 결함 수정, 실제 CSS 대비와 키보드 E2E                              |
| 문서 검토           | 제품 우선 README, 배포 준비/완료 구분, 미실행 구분         | validation.md / deployment.md / README                                         |

## 반영·수정·제외

반영: 오늘/전체 구분, 제목 입력, 날짜·완료·복구 규칙, 시스템 폰트, 네 화면 크기 검증. 수정: native dialog에만 의존했던 포커스 복귀·Tab 경계, 잘못된 timestamp 날짜 검증, 복원 후 포커스, 모바일 visualViewport 처리. 테스트 수정: 즉시 사라지는 행에는 check() 사후 checked 확인 대신 실제 클릭·저장 데이터·목록 이동을 확인하고, Windows 화면 배율을 고정해 의도한 CSS viewport를 검증했다.

제외: 원문에서 권장 예시로 나온 AI 음성 입력, 반복·캘린더·대량 편집, 많은 최상위 화면. 사용자 최종 명세와 핵심 경험의 완결성을 우선했다. 가짜 공개 링크, 자동 예시 삽입, 실제 사용자 검증/스마트폰 테스트를 수행했다는 표현도 사용하지 않았다.

## AI 판단의 한계

자동 생성 코드는 TypeScript·lint·규칙 테스트·실제 Chrome·원격 Chromium으로 검증하고 결함을 수정했으나 전체 보안 감사·WCAG 적합성 평가·실제 사용자 연구를 대체하지 않는다. 명세에는 없는 외부 계정·백업 기능을 약속하지 않는다. 남은 환경과 실제 배포 결과는 [검증](validation.md)과 [제출·배포](deployment.md)에 명시한다.
