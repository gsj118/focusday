# AI 활용 과정과 실제 결과

이 과제는 AI 활용을 제품 안의 기능이 아니라 **제작 과정**으로 보여준다. 같은 Codex 세션이 자료를 해석하고 구현·자체 검토·도구 실행·수정·문서화를 수행했다. 별도 모델, subagent 또는 사람 검토는 수행하지 않았다. 브라우저와 테스트 도구에서 나온 결과를 AI 판단과 구분한다.

## 실제 요청

- [최초 제작 지시](ai-prompts/01-implementation.md): 사용자가 실행을 명시적으로 요청한 첨부 명세. 원본 그대로 보존.
- [현재 사용자 실행 요청](ai-prompts/00-user-request.md): 현재 폴더 개발·검증·README 순서·커밋·조건부 push 요구.
- [공개 저장소 생성 후속 요청](ai-prompts/03-publication-request.md): 저장소 선택을 맡긴 후 실제 계정 확인·생성·push·Pages 배포·공개 주소 검증.
- [자체 검토 기록](ai-prompts/02-review-notes.md): 별도 대화가 있었던 것처럼 만든 프롬프트가 아니라, 이 세션에서 실제 수행한 검토와 결과.
- [v1.1 개발 명세 원문](ai-prompts/04-v1.1-implementation.md) · [v1.1 실행 요청](ai-prompts/05-v1.1-user-request.md): 계획·어제 이어가기·JSON 백업 확장과 기존 데이터/검증 보존.

## 반영·수정·제외

반영: 오늘/전체 구분, 제목 입력, 날짜·완료·복구 규칙, 시스템 폰트, 네 화면 크기 검증. 수정: native dialog에만 의존했던 포커스 복귀·Tab 경계, 잘못된 timestamp 날짜 검증, 복원 후 포커스, 모바일 visualViewport 처리. 테스트 수정: 즉시 사라지는 행에는 check() 사후 checked 확인 대신 실제 클릭·저장 데이터·목록 이동을 확인하고, Windows 화면 배율을 고정해 의도한 CSS viewport를 검증했다.

제외: 원문에서 권장 예시로 나온 AI 음성 입력, 반복·캘린더·대량 편집, 많은 최상위 화면. 사용자 최종 명세와 핵심 경험의 완결성을 우선했다. 가짜 공개 링크, 자동 예시 삽입, 실제 사용자 검증/스마트폰 테스트를 수행했다는 표현도 사용하지 않았다.

## v1.1 실제 작업

깨끗한 `bb8f852` 기준점에 v1.0.0 태그를 남기고 기존 문서·화면·증거를 복사한 뒤 baseline 검사부터 다시 실행했다. 첨부를 실행 명세로, 기존 리서치를 근거 자료로 구분했다. 저장 version:1과 key를 유지하는 순수 규칙을 먼저 만들고 validator를 로드/복원에서 공유했다.

계획/데이터 관리 보조 패널을 기존 native dialog·반응형 CSS와 연결했다. 원래 일반 변경의 실패 동작은 메모리 변경을 남기므로 복원에는 그대로 적용하지 않고, 단 한 번의 저장 성공 뒤 state를 바꾸는 경계를 별도로 구현했다. 같은 id는 현재 항목 유지, 교체는 확인 단계, 보호 guard는 우회하지 않도록 검토했다.

실제 모바일 화면 검토에서 미리보기가 파일 입력 아래 가려지는 문제를 확인해 자동 포커스/스크롤을 보완했다. 날짜가 바뀐 패널에 오래된 선택 피드백이 남을 가능성도 현재 날짜 조건으로 보완했다. 그 뒤 기존 25개 회귀와 새 30개 브라우저 검사를 production 앱에서 함께 실행해 55개 PASS를 확인했다. 후보·어제·복원·파일 오류·저장 실패·keyboard·touch와 네 화면 캡처가 포함된다.

새 사용자 연구를 수행하지 않았으므로 가설·실제 UI 경로·도구 결과를 구분했다. [변경 전후와 검토 기록](V1_1_UPDATE.md), [최신 검증](validation.md), [보존한 baseline](versions/v1.0.0/index.md)에 연결한다. 별도 모델·subagent·사람 평가를 실행했다는 기록은 없다.

## AI 판단의 한계

자동 생성 코드는 TypeScript·lint·규칙 테스트·실제 Chrome·원격 Chromium으로 검증하고 결함을 수정했으나 전체 보안 감사·WCAG 적합성 평가·실제 사용자 연구를 대체하지 않는다. 명세에는 없는 외부 계정·백업 기능을 약속하지 않는다. 남은 환경과 실제 배포 결과는 [검증](validation.md)과 [제출·배포](deployment.md)에 명시한다.

## v1.2 Synthetic Beta 실제 작업

[v1.2 실행 명세 원문](ai-prompts/06-v1.2-synthetic-beta.md)과 [실제 요청](ai-prompts/07-v1.2-user-request.md)을 적용했다. 같은 세션이 12개 목표·기기·제약 관점을 분리해 실제 Chrome 조작과 기존 E2E 재실행으로 평가했다. 별도 모델·subagent·실제 참여자·인터뷰·발화·만족도·사람의 과업 시간은 없었다.

시작 main7ff35e7과 기존 tag/source 관계를 확인하고 문서/화면/증거를 보존했다. 기존 단위42·시간대각22·E2E55 baseline을 실행하고, 새로운 세션 helper는 초기 실패를 기록한 채 계속했다. 따라서 스크립트12개 종료를 모두 기능PASS로 취급하지 않았다. 스크립트 selector/updatedAt 기대/disabled 해제 오류는 앱 결함과 분리해 원본·보완 재실행을 남겼다.

6000개 pure-data 크기 문제를 byte 단위로 재현하고 실제 UI 다운로드/다시 선택의 실패도 보존했다. 상세 분류 compositionstart+Enter의 의도하지 않은 저장도 raw hash와 모달 종료로 재현했다. 두 P1을 수정한 뒤 단위46·시간대각22·루트/Pages 각각71 E2E를 실행했다. 53개 Case의 원문 행동/기대와 실제 시각·환경·fixture·저장 assertion·근거를 매핑했다.

가상 관점의 버튼 발견/검색 혼동은 AI walkthrough 가설로 남겼다. 한도를 넘는 자체 데이터 전체의 파일 보존, 물리기기/OS IME/native 확대/스크린 리더·전체WCAG 미실행도 명시했다. 자동화 시간을 사람의 과업 시간이나 독립 평가 점수로 사용하지 않았다. [Synthetic Beta](SYNTHETIC_BETA_V1_2.md) · [실제 변경](V1_2_UPDATE.md) · [검증](validation.md).
