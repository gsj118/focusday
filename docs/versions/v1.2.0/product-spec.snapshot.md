# Focusday v1.2.0 제품 명세

## 목적과 범위

생각난 일을 빠르게 담고 오늘 실행할 일만 고르는, 계정 없는 개인용 로컬 앱. 주 사용자는 관리 체계·설정을 오래 유지하고 싶지 않은 개인이라는 **설계 가설**이다.

React + TypeScript + Vite + CSS + localStorage. 최상위 탐색은 오늘/전체. 로그인, 서버, DB, 클라우드 동기화, 협업·공유, 캘린더, 시간별 일정, 반복·알림, 하위 작업, 메모·첨부, 습관, 포모도로, 게임화, 앱 내부 AI, 음성/NLP, 드래그, 대량 편집, 테마·다크 모드, PWA는 제외한다.

## 데이터

`AppData = { version: 1, tasks: Task[] }`, 저장 키 `focusday:v1`.

| 필드                  | 규칙                                                       |
| --------------------- | ---------------------------------------------------------- |
| id                    | 고유 문자열. 새 항목은 crypto.randomUUID                   |
| title                 | trim, 필수, 최대 200자(입력과 JavaScript 문자열 길이 기준) |
| createdAt / updatedAt | ISO UTC timestamp                                          |
| completedAt           | ISO UTC timestamp 또는 null                                |
| dueDate / focusDate   | 유효한 로컬 달력 날짜 YYYY-MM-DD 또는 null                 |
| priority              | none / low / medium / high → 없음 / 낮음 / 보통 / 높음     |
| category              | 단일 선택적 문자열, trim 후 최대 24자 또는 null            |
| isDemo                | boolean, 직접 만든 항목은 항상 false                       |

## 생성·보기·검색

오늘에서 생성하면 focusDate=오늘, 전체에서 생성하면 null. dueDate=null, priority=none, category=null, completedAt=null. 성공 후 입력을 비우고 포커스를 유지한다. 공백만 입력하면 오류를 안내한다. IME 조합 중 Enter, keyCode 229와 조합 종료 직후 같은 Enter는 제출하지 않는다.

오늘의 미완료 포함 조건은 `focusDate === today || (유효한 dueDate !== null && dueDate <= today)`이다. 기한 초과는 별도 섹션에 먼저 표시하고 나머지 오늘 항목과 중복시키지 않는다. 전체에는 모든 미완료가 있다. 완료는 전체의 접을 수 있는 영역에 제공한다.

검색은 현재 보기의 제목·분류에서 대소문자를 구분하지 않는 부분 문자열 검색이다. 전체에서는 완료도 포함하고 검색 중 완료 영역을 펼친다. 탐색 메뉴 수는 검색과 무관한 미완료 수, 검색 결과 수는 현재 보기의 검색 일치 수다.

## 정렬

- 오늘 기한 초과: 오래 지난 기한 → 높은 우선순위 → 먼저 생성 → id.
- 오늘 나머지: 높은 우선순위 → 먼저 생성 → id.
- 전체: 오늘/기한 초과 → 미래 기한 → 나머지. 각 그룹 안은 높은 우선순위 → 먼저 생성 → id.
- 완료: 최근 완료 → id. id는 동률의 안정적인 기준이다.

## 오늘 선택과 기한

집중하기/집중 해제는 focusDate를 변경하고 updatedAt을 갱신한다. id·기한·그 밖의 속성은 유지한다. 기한이 오늘/과거이면 집중을 해제해도 오늘에 남는다. “집중은 해제했습니다. 기한 때문에 오늘에도 표시됩니다.” 안내와 기한 편집 버튼을 제공한다. 편집기에서도 원인을 알려준다.

getFullYear/getMonth/getDate로 오늘을 구한다. 날짜 더하기는 로컬 달력의 setDate로 처리하며 시간은 정오로 설정한다. 날짜 간 차이는 달력 성분으로 계산해 DST의 23/25시간과 분리한다. 자정 타이머, window focus, visibilitychange에서 오늘과 다음 자정 타이머를 갱신한다. 지난 focusDate는 오늘에서 빠지지만 전체의 항목은 삭제하지 않는다.

## 편집·완료·복구

동일 편집기가 데스크톱 우측 모달 drawer, 모바일 bottom sheet로 열린다. 제목·오늘 집중·기한 설정/해제·우선순위·분류·보조 삭제를 제공한다. 저장만 적용하며 취소/Escape는 초안을 버린다. 빈 제목과 잘못된 날짜는 저장을 막는다.

native dialog와 명시적인 Tab 경계 유지, 최초 제목 포커스, 닫힌 후 호출 지점으로 복귀를 제공한다. 행이 사라지면 인접 항목 또는 입력창으로 포커스를 옮긴다. 모바일 편집기는 visualViewport 크기 변경을 반영한다.

완료는 completedAt을 기록한다. 전체 완료 영역에서 복원할 수 있다. 완료/삭제는 최근 한 건만 8초 실행 취소한다. hover와 키보드 포커스 동안 남은 시간을 멈추며 새 완료/삭제는 이전 알림을 교체한다. 토큰과 component key로 이전 타이머를 격리한다. 삭제 취소는 원래 Task 전체를, 완료 취소는 해당 항목의 완료 여부만 복원해 다른 속성 변경을 유지한다. 예시 데이터 제거는 예시용 일괄 관리이므로 삭제 취소 대상이 아니며 표시 중인 복구 정보도 해제한다.

## 저장·복구 상태

- 초기 load는 읽기만 수행한다. 기본 빈 값의 자동 저장 effect는 없다.
- 접근/읽기 실패: 자동 쓰기 차단, 다시 읽기. 성공 시 기존 항목과 메모리 항목을 id로 합친다.
- JSON/스키마/버전 오류: 원본 보존, 다운로드, 별도 명시적 초기화 확인.
- 쓰기 실패: 메모리 변경은 유지, 지속 경고·저장 재시도. 실제 다음 쓰기 성공 때만 실패 상태를 해제한다.
- 저장됨은 setItem 성공 후에만 표시한다. 초기 정상 데이터 읽기는 ‘로컬 데이터 불러옴’으로 표시한다.
- 초기화는 손상 원본을 현재 탭 목록으로 교체한다. setItem 실패 시 원본을 유지한다.

## 선택형 예시·빈 상태

현재 날짜에 맞춘 예시 5개는 사용자가 선택한 때만 추가하고 “예시 5개를 추가했습니다.”를 표시한다. 기존 예시가 하나라도 있으면 저장 호출 없이 “예시가 이미 추가되어 있습니다.”를 표시한다. 예시 제거는 isDemo=true만 제거하고 직접 작성한 항목을 보존한다.

첫 빈 화면, 오늘만 빈 화면, 전체 미완료 없음, 검색 결과 없음, 읽기/쓰기 오류를 별도로 안내한다. 검색 지우기, 첫 입력, 전체 보기, 예시, 재시도 등 다음 행동을 제공한다.

## 접근성과 시각 기준

semantic HTML, 이름 있는 native 입력/버튼/체크박스, 명확한 focus ring, status/alert, 텍스트로 기한·우선순위, reduced-motion을 사용한다. 핵심 터치 영역은 44px 이상을 목표로 한다. N 새 입력, / 검색은 일반 입력·IME·조합키·편집/확인 모달에서 가로채지 않는다. 일반 텍스트 대비와 실제 검증 범위는 [검증 기록](validation.md)에 있다. 전체 WCAG 준수 판정은 하지 않았다.

## 오늘 계획하기와 어제 이어가기

최상위 탐색은 오늘/전체 두 개를 유지한다. 오늘 계획하기는 오늘 화면의 보조 행동으로 열리는 단일 native dialog다. 데스크톱은 drawer, 모바일은 bottom sheet이며 기존 편집기·데이터 관리와 중첩되지 않는다.

미완료만 후보로 제시하고 기한 초과 → 오늘 기한 → 로컬 달력의 어제 focusDate → 높은 우선순위 순서로 한 번만 배치한다. 여러 조건을 만족하면 상위 그룹에 배치하고 충족한 사실 이유를 모두 보여준다. 기한 초과 안은 오래 지난 기한 → 기존 우선순위/생성/id 순서, 나머지 그룹은 기존 우선순위/생성/id 순서다. 이미 오늘 집중인 후보는 집중 중 상태를 보여준다.

항목별 집중하기/집중 해제는 기존 저장·오류 처리로 즉시 적용한다. 별도 일괄 선택·개수 제한·AI 추천은 없다. 후보가 없으면 빈 상태와 전체 보기 경로를 제공한다. 선택 후 후보 조건을 벗어나는 어제 항목은 후보에서 빠지고 오늘 목록에 표시된다. 선택 피드백을 제공하고 사라진 버튼의 포커스는 패널 닫기로 이동한다.

어제 안내 수는 `completedAt === null && focusDate === addDays(today, -1)`이다. 기한으로 이미 오늘에 표시되는 항목도 count에 포함할 수 있지만 복제하거나 목록에 두 번 표시하지 않는다. 완료·이틀 이상 지난 집중은 어제에서 제외한다. 자동 이월·자동 팝업은 없다. 자정·focus·visibilitychange에서 안내·후보·요약을 함께 계산한다.

오늘 요약은 미완료 중 focusDate=오늘의 직접 집중 수와, 유효한 dueDate≤오늘이며 focusDate≠오늘인 기한 표시 수다. 두 집합은 겹치지 않고 합계는 검색 전 오늘 미완료 수와 같다.

## JSON 백업·복원

예시 및 앱 정보 메뉴에서 보조 패널을 연다. 전체 현재 메모리 목록을 `format: "focusday-backup"`, `formatVersion:1`, `exportedAt: ISO UTC`, `data:{version:1,tasks:[]}`로 다운로드한다. 파일명은 `focusday-backup-로컬날짜.json`이다. 완료·예시·모든 속성을 포함하고, 쓰기 실패 중의 아직 저장하지 못한 변경도 포함한다. 저장 보호 중에는 현재 탭 목록만 포함하고 원본은 포함하지 않음을 알린다. 내보내기는 저장을 호출하지 않으며 Object URL을 해제한다.

파일 최대 크기는 10MiB다. JSON·정식 format/version·exportedAt·기존 저장 스키마·모든 필드/길이/달력 날짜/timestamp/id 중복을 동일 validator로 확인한다. 파일 선택·취소·검증 실패는 앱 데이터와 저장 상태를 바꾸지 않는다. 유효하면 전체/미완료/완료 수와 방식 미리보기를 표시하고 해당 제목으로 포커스/스크롤을 옮긴다. 늦은 파일 읽기는 다음 선택과 닫힌 패널을 변경하지 않는다. raw 원본 다운로드를 정식 백업으로 취급하지 않는다.

기본 합치기는 현재 항목을 모두 유지하고 백업의 새 id만 추가한다. 중복 id와 내용이 다른 중복 수를 별도로 보여주며 현재 항목을 유지한다. 같은 제목이어도 다른 id는 별도 항목이다. 전체 교체는 현재/복원 개수 → 같은 패널의 확인 단계 → 명시적 교체 버튼을 거치며 교체 전 백업과 취소를 제공한다.

완성된 결과를 한 번의 saveData 호출로 저장한다. 성공한 뒤에만 메모리/목록을 바꾸고 완료를 표시한다. 실패하면 기존 메모리·저장 원본·전역 저장 상태를 유지하고 패널에 복원 오류·재시도·취소를 제공한다. blocked/unavailable은 복원으로 우회하지 않는다. 성공 후 이전 실행 취소·편집·검색을 정리하고 보기·후보·개수를 새 데이터로 계산한다.

앱 버전은 1.2.0이지만 저장 형식은 v1.0과 동일하다. 로그인·서버·자동 백업·동기화는 없다. 파일은 사용자가 직접 보관하는 사본이다.

## v1.2 입력·백업 보완

상세 편집에서도 composition 이벤트 중, native isComposing/keyCode229, 조합 종료 직후 80ms의 Enter를 제출로 처리하지 않는다. textarea의 일반 Enter는 줄바꿈이고, 유효한 분류 입력 Enter와 저장 버튼 활성화는 저장한다. 실제 OS IME 검증과 구분한다.

백업은 전체 데이터를 compact JSON으로 직렬화한 후 UTF-8 byte를 검사한다. 10MiB 이내만 정식 백업으로 다운로드하고 크기도 안내한다. 초과하면 이유를 표시하고 다운로드를 중단한다. 목록·원본은 유지하며 부분 항목 제외나 분할은 하지 않는다. 기존 padded JSON 파일과 formatVersion1은 지원한다. 지원 범위를 넘는 미저장 메모리 전체 데이터의 파일 보존은 보장하지 않는다.
