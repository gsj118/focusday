# Focusday v1.1.0 업데이트 기록

## 관찰과 설계 가설

v1.0에서 확인한 구조는 전체 목록의 개별 집중 버튼, 지난 focus가 오늘에서 빠지는 규칙, 한 브라우저 localStorage에만 저장하는 방식이다. 관리할 항목이 쌓였을 때 오늘 고를 일을 찾거나 어제 일을 이어갈 별도 진입점이 없고, 정상 데이터의 백업·복원 UI도 없었다.

후보와 어제 안내가 탐색 부담을 줄이고 수동 파일 백업이 사용자의 보존 선택을 늘린다는 것은 **설계 가설**이다. 사용자 인터뷰·실험·만족도 측정은 하지 않았다. 실제로 검증한 것은 아래 앱 경로와 데이터·오류·브라우저 동작이다.

## 기준점과 호환성

기준 커밋 `bb8f852`, 태그 `v1.0.0`. 시작 시 작업 트리는 깨끗했고 적용되는 AGENTS.md나 다른 실습 폴더가 없었다. 기존 Git identity와 `gsj118/focusday`를 확인했다. [v1.0 문서·화면](versions/v1.0.0/index.md)과 [개발 전 재실행](evidence/v1.1/baseline-v1.0.json)을 보존했다.

앱/package 버전은 1.1.0이다. `focusday:v1`과 데이터 `{version:1,tasks:[]}`는 그대로이며 마이그레이션·초기화 없이 기존 필드 전체를 읽는다. 기존 v1 데이터 주입 후 첫 렌더의 raw 문자열/저장 호출 0을 브라우저에서 확인했다. 사용자의 실제 브라우저 프로필 데이터는 테스트에 사용하지 않았다.

## 실제 경로의 변경 전후

| 과업                           | v1.0에서 확인한 경로                                              | v1.1에서 확인한 경로                                                                  | 달라진 범위                                                                     |
| ------------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 쌓인 일 중 오늘 집중할 일 선택 | 오늘 → 전체 → 목록 탐색 → 항목별 오늘에 추가 → 오늘               | 오늘 → 오늘 계획하기 → 그룹/이유 확인 → 항목별 집중하기 → 오늘 목록                   | 전체를 오가지 않고 기한·어제·높음 후보 선택 가능. 후보 밖은 기존 전체 경로 유지 |
| 어제 미완료 이어가기           | 지난 focus는 오늘에서 빠짐. 전체에서 해당 항목을 찾아 오늘에 추가 | 오늘의 ‘어제 마치지 못한 일 N개’ 확인 → 계획 → 어제 그룹 또는 상위 기한 그룹에서 선택 | 로컬 어제 조건과 이유 표시. 기존 id·기한 유지, 자동 이월/복제 없음              |
| 전체 백업·복원                 | 정상 데이터용 UI 없음. 손상 시 raw 원본 다운로드만 제공           | 보조 메뉴 → 백업·복원 → JSON 다운로드 / 파일 선택 → 미리보기 → 합치기 적용            | 완료·예시·모든 속성 포함. raw 원본은 정식 백업과 구분                           |
| 전체 교체                      | 전용 경로 없음                                                    | 파일 미리보기 → 전체 교체 선택 → 확인 단계 → 교체 전 백업 또는 취소 → 명시적 교체     | 1회 저장 성공 후에만 목록 변경, 실패 시 원본과 메모리 유지                      |

위 경로는 실제 UI 조작과 E2E로 확인했다. 항목 탐색/스크롤 횟수는 데이터와 화면에 따라 달라지므로 고정 클릭 수, 사용자 시간 단축률, 만족도 향상을 주장하지 않는다. 자동화 duration은 과업 수행 시간 측정이 아니다.

## 구현과 안전 경계

- `src/domain.ts`: 로컬 어제·후보 그룹/이유·기존 정렬·겹치지 않는 오늘 요약.
- `src/backup.ts` / `src/storage.ts`: 기존 스키마 validator 공유, 정식 백업·5MiB·id 합치기/충돌 계산.
- `src/App.tsx`: 보호 guard·기존 저장 재시도, 복원의 저장 성공 후 적용, 오래된 undo/편집/검색 정리.
- `src/components/PlanPanel.tsx`, `DataPanel.tsx`, `PanelDialog.tsx`: 단일 보조 모달, 즉시 집중·미리보기/확인·키보드/포커스.
- `src/styles.css`: 기존 차분한 스타일, 13px 메타데이터, 네 폭과 visualViewport 대응.

파일 선택·취소·검증 실패는 저장을 하지 않는다. 기본 합치기는 현재 중복 id를 유지하고 다른 id의 같은 제목은 별도 추가한다. 전체 교체는 같은 패널 안에서 확인하며 중첩 모달을 만들지 않는다. 실패한 복원은 앱 메모리와 원본을 유지하며 전역 저장 상태도 그대로 둔다. blocked/unavailable 보호는 해제하지 않는다.

## 한계와 버전 기록

모바일은 Chrome touch/isMobile 에뮬레이션이며 실제 스마트폰·실제 키보드/safe-area 검증은 하지 않았다. OS 한글 IME는 이벤트 수준, Safari/Firefox·스크린 리더·전체 WCAG·사용자 연구·성능 벤치마크는 미실행이다. 서버 백업·자동 동기화·다중 탭 동시 편집을 보장하지 않는다. 정식 복원 파일 한도는 5MiB이며 파일은 사용자가 직접 보관한다.

기준 태그·출시 태그·커밋·push·CI·수동 Pages 배포의 최종 상태는 [배포 문서](deployment.md)에 기록한다. [CHANGELOG](../CHANGELOG.md) · [실행을 요청한 명세 원문](ai-prompts/04-v1.1-implementation.md) · [사용자 요청](ai-prompts/05-v1.1-user-request.md).
