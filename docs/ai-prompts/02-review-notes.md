# 같은 세션에서 수행한 자체 검토

이 문서는 추가 사용자 메시지나 별도 모델 프롬프트를 받은 것처럼 꾸민 기록이 아니다. 실제 구현 중 적용한 검토 질문과 도구 결과를 보존한다.

## 저장·날짜·복구 검토

검토 질문: 처음 읽기 전에 쓰는가? JSON·스키마·버전 손상을 덮어쓰는가? 읽기 실패 후 기존 데이터를 지우는가? 쓰기 실패인데 저장됨을 표시하는가? 오늘 집중과 기한을 혼동하는가? UTC 날짜/DST가 포함 규칙을 바꾸는가? 항목 단위 복구가 다른 편집을 되돌리는가? 이전 타이머가 새 복구를 만료시키는가?

결과: 읽기/쓰기 경계와 원본 보호 채택. 읽기 재시도에서 기존+메모리 항목을 병합. timestamp 검사에 실제 달력 날짜와 시간 범위를 추가. 토큰·component key로 타이머 격리, 남은 시간만 일시 정지. 전체 스냅샷 rollback은 다른 항목의 편집을 지우므로 채택하지 않음.

## UX·모바일 검토

검토 질문: 제목만으로 생성 가능한가? 오늘 제거가 기한 때문에 남으면 이유와 편집 경로가 보이는가? 320px·200자·공백 없는 문자열이 넘치는가? 시트/탐색/실행 취소가 겹치는가? 예시 제거가 사용자 항목을 지우는가?

결과: 실제 네 viewport의 목록/편집기 스크린샷 확인. 기한 잔류 안내와 기한 편집 연결. visualViewport를 이용한 좁아진 가시 영역 대응. 예시 자동 삽입과 추가 통계 카드·설정 화면은 제외.

## 접근성·검증·문서 검토

검토 질문: 키보드로 편집을 닫으면 원래 행으로 돌아가는가? 첫/끝 Tab이 모달에 머무는가? 행이 사라져도 포커스가 유지되는가? 실제 상태별 글자 대비와 입력 이름이 있는가? 수행하지 않은 테스트나 공개 배포를 성공으로 적는가?

결과: 첫 브라우저 검증에서 Escape 후 포커스 유실 발견. requestAnimationFrame 의존을 DOM 갱신 후 useLayoutEffect 복구로 수정. native dialog의 Tab 경계에 명시적인 경계 처리 추가. 완료 복원 시에도 인접 항목/입력창으로 복귀. README 상단을 제품→실제 화면→시연 상태/실행→차별점 순서로 구성. 실제 OS IME·휴대폰·Safari/Firefox·사용자 연구·GitHub Actions 실행은 미실행으로 구분.

## 테스트 도구 자체의 수정

완료 직후 행이 없어지므로 Playwright check()의 사후 checked 확인이 대기했다. 클릭으로 행동을 수행하고 저장 데이터와 목록/완료 영역을 검증하도록 수정했다. 기대 동작을 제거하지 않았다. Windows 배율 때문에 요청한 1366px가 실제 fractional layout 1366.4px로 나타나 scale factor를 고정했다. 테스트의 viewport 경계 기대를 완화하지 않았다. 로컬 preview가 다른 테스트의 종료로 중지된 실행은 연결 실패로 구분하고 독립적인 preview에서 다시 실행했다.
