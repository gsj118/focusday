현재 Focusday 프로젝트를 **v1.1.0 ‘오늘 계획과 지속 사용 개선’**으로 실제 업데이트해 주세요. 이 메시지는 현재 작업 폴더에서 구현·검증·문서화·GitHub 반영까지 진행하라는 명시적인 요청입니다. 계획이나 문서 검토만으로 끝내지 말고 개발을 시작해 주세요.

기존 v1.0 코드, README, docs/product-spec.md, docs/decisions.md, docs/validation.md, AI 활용 기록과 리서치를 먼저 확인하세요. 기존 사용자 작업을 보존하고, 현재 구현을 기준으로 수정하세요. 이번 버전의 명시적인 확장 요구는 최초 제작 프롬프트의 범위 제한보다 우선합니다. 그 밖의 제외 기능은 유지합니다.

## 1. 버전 목표와 기본 원칙

v1.0은 빠른 입력, 오늘/전체, 기한과 집중 분리, 완료·복구, 로컬 저장을 완성했습니다. v1.1은 **쌓인 일 중 오늘 할 것을 선택하고, 어제 미완료를 이어가며, 데이터를 직접 보존하는 경험**을 개선합니다.

핵심 변경:
1. 오늘 계획하기.
2. 어제 미완료 집중 항목 이어가기.
3. JSON 백업·복원.
4. 위 경험을 뒷받침하는 문구·가독성·피드백 개선.

이 사용자 문제는 현재 구조에서 도출한 설계 가설입니다. 실제 사용자 연구로 확인했다고 기록하지 마세요.

React·TypeScript·Vite·일반 CSS·localStorage와 계정 없는 제품 방향을 유지하세요. 오늘/전체 두 최상위 메뉴를 유지하고, 계획과 데이터 관리는 보조 패널로 제공합니다. 로그인, 서버, 동기화, 캘린더, 반복, 알림, 포모도로, 앱 내부 AI 등은 추가하지 마세요.

화면의 차분한 디자인을 유지하면서 기존 컴포넌트와 로직을 재사용하세요. 이미 검증된 구조를 불필요하게 전면 교체하지 마세요.

## 3. 오늘 계획하기와 어제 이어가기

오늘 화면에 명확한 보조 행동 **‘오늘 계획하기’**를 제공합니다. 데스크톱에서는 패널 또는 drawer, 모바일에서는 bottom sheet로 구현하고 기존 편집기와 중첩된 모달을 만들지 않습니다.

이 경험의 목적은 전체 목록을 오가며 하나씩 찾는 부담을 줄이는 것입니다. 별도 대시보드나 복잡한 추천 설정을 만들지 마세요.

### 후보 규칙

브라우저 로컬 날짜를 기준으로 미완료 항목만 후보로 제시합니다.

우선순위:
1. 기한 초과.
2. 오늘 기한.
3. 어제 집중 대상으로 선택했지만 완료하지 않은 항목.
4. 위 조건에 속하지 않는 높은 우선순위 항목.

- 각 항목은 한 번만 표시합니다. 여러 조건을 만족하면 상위 그룹에 배치하고 필요한 이유를 함께 표시합니다.
- 그룹 안은 기존 정렬 규칙을 재사용하고 동률 기준을 안정적으로 유지합니다.
- 후보 제시 이유는 ‘기한 초과’, ‘오늘 기한’, ‘어제 선택한 일’, ‘높은 우선순위’처럼 사실에 근거해 표시합니다.
- AI 추천·최적의 계획·예상 완료 시간처럼 구현하지 않은 판단을 주장하지 않습니다.
- 오늘 이미 집중 중인 후보는 ‘집중 중’ 상태를 표시합니다. 중복 생성하지 않습니다.
- 후보가 없는 경우 명확한 빈 상태와 ‘전체 할 일 보기’ 경로를 제공합니다.
- 이 패널은 전체 목록을 대체하지 않습니다. 후보 밖의 작업도 기존 전체 보기에서 집중 대상으로 선택할 수 있어야 합니다.

후보의 **‘집중하기 / 집중 해제’**는 focusDate만 변경합니다. 항목별 선택을 즉시 적용하고 기존 저장 상태·오류 처리를 공유합니다. 일괄 선택, 강제 개수 제한, 새 드래그 기능은 넣지 않습니다.

### 어제 미완료 이어가기

어제 미완료 조건:
completedAt === null AND focusDate === 로컬 달력의 어제.

- 어제는 기존 addDays(today, -1) 등 달력 연산으로 계산합니다. UTC 날짜 잘라내기를 사용하지 않습니다.
- 오늘 화면에서 해당 항목이 있을 때만 ‘어제 마치지 못한 일 N개’와 ‘오늘 계획하기’ 진입을 제공합니다.
- 이 수는 현재 날짜에 따라 다시 계산합니다. 별도의 매일 초기화 데이터나 자동 팝업을 만들 필요는 없습니다.
- 사용자가 이어가기를 선택하면 기존 항목의 id와 dueDate를 유지하고 focusDate만 today로 변경합니다.
- 자동 이월·자동 완료·기한 변경·새 항목 복제는 하지 않습니다.
- 기한 때문에 오늘에 이미 표시되는 어제 항목도 중복 표시하거나 복제하지 않습니다.
- 완료한 어제 항목은 제외합니다. 이틀 이상 지난 집중 항목은 ‘어제’로 부르지 않고 기존 전체 목록에 유지합니다.
- 자정·window focus·visibilitychange에서 패널과 안내의 날짜 상태도 함께 갱신되어야 합니다.

## 4. 집중과 기한의 표현 개선

목록과 편집기의 개념을 다음으로 통일합니다.

- focusDate 선택: ‘집중하기 / 집중 해제’, 선택 상태 ‘오늘 집중’.
- dueDate: ‘오늘 기한 / 내일 기한 / 기한 초과’.
- 집중 해제 후 dueDate 때문에 오늘에 남으면:
  ‘집중은 해제했습니다. 기한 때문에 오늘에도 표시됩니다.’
  그리고 기존 기한 편집 경로를 유지합니다.

오늘 목록 포함 규칙은 그대로 유지합니다:
미완료 AND (focusDate === today OR dueDate <= today).
유효한 dueDate가 있는 경우만 날짜 비교합니다.

오늘 화면에 간결한 요약을 제공할 수 있습니다:
- 직접 집중으로 고른 N개: 미완료 중 focusDate === today.
- 기한으로 표시된 M개: 미완료 중 dueDate <= today이면서 focusDate !== today.

두 집합은 겹치지 않으며 합계는 오늘 미완료 수와 같아야 합니다. 날짜·완료·집중 변경 후 수치가 즉시 일치해야 합니다. 통계 카드나 성과 점수로 확장하지 않습니다.

날짜·우선순위·분류 등 기존 11px 메타데이터는 13~14px을 목표로 읽기 쉽게 조정하세요. 320px 화면과 긴 제목에서 줄바꿈·칩·버튼이 겹치지 않는지 확인합니다. 핵심 터치 영역, 대비, 포커스 표시를 유지합니다.

예시 재추가:
- 실제로 추가했을 때만 ‘예시 5개를 추가했습니다’라고 안내합니다.
- 기존 예시가 있어 추가하지 않았다면 ‘예시가 이미 추가되어 있습니다’라고 안내합니다.
- 예시 제거 시 실제 사용자 항목을 보존하는 기존 규칙은 유지합니다.

## 5. JSON 백업·복원

‘예시 및 앱 정보’ 같은 보조 메뉴에서 접근 가능한 데이터 관리 UI를 제공합니다. 일반 작업 화면의 중심을 데이터 설정으로 바꾸지 마세요.

### 백업

백업 파일 구조:
{
  "format": "focusday-backup",
  "formatVersion": 1,
  "exportedAt": "ISO timestamp",
  "data": { "version": 1, "tasks": [] }
}

- 전체 항목을 백업합니다. 미완료·완료·isDemo와 모든 기존 속성을 보존합니다.
- 파일명에 로컬 날짜를 포함합니다.
- 현재 메모리 데이터를 내보내며, 저장 실패 중이라면 아직 브라우저에 저장되지 않은 변경도 포함된다는 사실을 안내합니다.
- 내보내기가 앱 데이터나 저장 키를 수정하지 않아야 합니다.
- Object URL과 파일 입력 등 자원을 적절히 정리합니다.

### 파일 검증과 미리보기

파일을 선택한 순간 기존 데이터를 바꾸지 않습니다.

- JSON 파싱, format/formatVersion, data.version, 각 필드, 유효한 날짜·timestamp, 제목·분류 길이, 파일 내 id 중복 등을 검증합니다.
- 기존 저장 검증 규칙을 재사용하여 로드와 복원의 허용 기준이 달라지지 않게 합니다.
- 지원하지 않는 버전·잘못된 형식·5MiB 초과 파일에는 한국어 오류와 재선택 경로를 제공합니다.
- 파일 선택 취소나 검증 실패는 기존 데이터·저장 상태를 변경하지 않습니다.
- 검증을 통과한 뒤 전체·미완료·완료 항목 수와 복원 방식을 미리 보여줍니다.
- 기본 지원 형식은 위 정식 백업 형식입니다. 손상 데이터 원본 다운로드 파일을 검증 없이 복원 가능하다고 안내하지 않습니다.

### 복원 방식과 안전한 적용

기본값은 ‘기존 데이터에 합치기’입니다.
- id가 겹치지 않는 항목만 추가합니다.
- 같은 id는 현재 항목을 유지합니다.
- 추가될 항목 수, 중복으로 유지할 수, 내용이 다른 중복 항목 수를 안내합니다.
- 제목이 같아도 id가 다르면 별도 항목입니다. 제목만으로 임의 병합하지 않습니다.

선택적으로 제공하는 두 번째 방식은 ‘백업으로 전체 교체’입니다.
- 현재 항목 수와 교체 후 항목 수를 명확히 보여줍니다.
- 기존 목록이 대체된다는 확인 UI를 거친 후에만 적용합니다.
- 단순한 파일 선택이나 기본 버튼으로 교체가 실행되지 않아야 합니다.
- 교체 전 백업을 만들 수 있는 경로를 제공합니다.

두 방식 모두:
- 전체 결과를 준비한 뒤 한 번의 저장 호출로 적용합니다. 부분 적용하지 않습니다.
- 쓰기가 실제로 성공한 후에만 앱 목록을 갱신하고 복원 완료를 표시합니다.
- 저장 실패 시 적용 전 메모리 목록과 원본 저장 데이터를 유지하고 오류·재시도·취소를 제공합니다.
- 기존 저장 보호 상태가 blocked/unavailable이면 복원으로 보호를 우회하지 않습니다. 기존 복구 절차를 안내합니다.
- 성공 후 이전 항목을 대상으로 한 실행 취소·편집 초안 등 오래된 임시 상태를 정리합니다.
- 앱의 보기·검색·계획 후보·개수는 복원한 데이터로 일치하게 갱신합니다.
- 브라우저 localStorage의 기존 저장 보호 동작은 약화하지 않습니다.

백업 파일은 사용자가 직접 보관하는 사본이며 자동 서버 백업·동기화가 아닙니다.

## 6. 실제 검증과 변경 전후 비교

먼저 실행 가능한 기존 검사로 baseline을 확인하고, 이번 변경에 필요한 테스트를 추가하세요. 기존 핵심 동작은 회귀 검증합니다. 문구 변경으로 선택자가 바뀌면 테스트를 맞추되 데이터·복구·저장에 대한 기대 결과를 약화하지 않습니다.

새로 확인할 항목:
- 후보 그룹의 순서·중복 방지·선택 이유·완료 제외·후보 없음.
- 어제 미완료, 오늘 이어가기, 기존 id와 기한 유지, 자동 이월 없음.
- 월말·연말·서울/뉴욕 날짜 경계와 앱이 열린 상태의 자정 전환.
- 직접 선택 수와 기한 표시 수의 중복 없는 합계.
- 집중 해제 후 기한 잔류 안내.
- 백업 round trip과 모든 속성·완료·예시 상태 보존.
- 파일 취소·손상·버전 불일치·중복 id·큰 파일 처리.
- 합치기의 중복 규칙, 교체 미리보기·확인·취소.
- 복원 쓰기 실패의 원본 보존, 재시도와 저장 보호 상태.
- 예시 재추가의 정확한 피드백.
- 계획·데이터 관리 패널의 키보드·Escape·포커스 복귀.
- 1440×900, 1366×768, 390×844, 320px에서 새 화면·긴 제목·메타데이터·하단 UI.
- 기존 CRUD·완료/삭제 취소·저장 오류·검색·예시·날짜 갱신.
- 타입 검사, lint, 단위·시간대·브라우저 테스트, production build, Pages 하위 경로와 실제 배포 로딩.

변경 전후 비교는 다음 과업을 중심으로 기록합니다:
1. 전체 할 일에서 오늘 집중할 일을 고르기.
2. 어제 미완료 항목을 찾아 오늘 이어가기.
3. 전체 데이터를 백업하고 복원하기.
