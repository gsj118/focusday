# Focusday v1.4 최종 구현·Synthetic Beta·마무리 수정 요청

현재 작업 폴더의 Focusday를 v1.4.0 최종 제출 버전으로 완성하라. 아래 세 기능을 실제 구현한 뒤, 다양한 가상 사용자 관점의 연결된 사용 시나리오를 실제 앱에서 수행하고, 발견한 문제를 수정·재검증·문서화·배포하라. 제안서나 테스트 계획만 작성하고 멈추지 않는다.

- 저장소: https://github.com/gsj118/focusday
- 공개 사이트: https://gsj118.github.io/focusday/
- 확인한 기준: 노션 작업 UI로 교체된 v1.3.0

작업 시작 시 실제 체크아웃·브랜치·원격 상태를 확인한다. 더 최신 변경이나 사용자 작업이 있으면 보존하고, 되돌리기·초기화·force push로 덮어쓰지 마라. 이 요청의 목표는 새 기능 세 가지와 최종 품질 개선이다. 다시 디자인 선택지를 묻지 말고 아래 기준으로 세부 결정을 내려 완성하라.

## 1. 범위와 제품 방향

이번에 추가할 기능은 다음 세 가지로 한정한다.

1. 오늘의 한 문장: 차분한 문구 / 유머 / 내 문장 / 끄기
2. 완료 순간의 격려: 첫 완료와 정해진 성취 시점의 절제된 피드백
3. 오늘의 성취 기록: 오늘 완료한 실제 사용자 항목과 개수

v1.3의 노션 스타일, 빠른 입력, 오늘 집중과 기한의 구분을 유지한다. 명언 카드·통계 대시보드·축하 팝업을 크게 추가해 작업 목록을 밀어내지 않는다. 로그인·동기화·서버·외부 API·AI 생성 API·실시간 밈 수집·점수·레벨·연속 달성·보상 상점·타이머·주간 회고·반복 작업 등은 추가하지 마라.

목표는 “정돈된 작업 앱에 작은 격려와 성취 확인을 더한 최종 버전”이다. 며칠 쓰지 않았다고 비난하거나, 미완료 때문에 실패·점수 하락·연속 기록 단절을 강조하지 않는다.

## 2. 시작 전 확인과 baseline

README.md, DESIGN.md, CHANGELOG.md, package.json, docs/product-spec.md, docs/decisions.md, docs/validation.md, docs/deployment.md, docs/V1_3_UI_REDESIGN.md와 관련 코드를 읽는다. 특히 다음을 이해한다.

- src/App.tsx, src/styles.css, src/domain.ts, src/storage.ts, src/backup.ts
- TaskRow, TaskEditor, PlanPanel, DataPanel, PanelDialog, UndoToast
- 로컬 날짜·자정 처리, IME 조합 보호, 실행 취소, 저장 보호, 백업·복원
- 기존 단위·날짜·E2E 테스트와 Pages workflow

확인 당시 React + TypeScript + Vite + 일반 CSS, Node.js 24 / pnpm 11.19.0을 사용한다. 실제 package.json을 기준으로 기존 기술과 lockfile을 유지하고 불필요한 의존성을 추가하지 마라.

작업 전 pnpm check와 기존 E2E를 실제 실행해 baseline을 기록한다. v1.3 문서에 기록된 E2E 80개 통과를 이번 실행 결과로 복사하지 마라. 기존 실패와 새 회귀를 구분한다. 기존 시험 결과·태그·스크린샷은 보존한다.

## 3. 오늘의 한 문장

### 표시와 설정

- 오늘 보기의 기존 제목 아래 설명 한 줄을 활용한다. 추가적인 큰 카드나 자동으로 열리는 팝업을 만들지 않는다.
- 전체 보기의 안내 문구와 오류·저장 안내는 그대로 유지한다.
- 기본값은 “차분한 문구”다. 설정에서 “차분한 문구 / 유머 / 내 문장 / 끄기”를 선택한다.
- 끄기에서는 기존 제품 안내 문장을 보여준다. 영역을 어색하게 비우거나 새 안내 문구를 반복해서 추가하지 않는다.
- 설정은 기존 앱 정보 메뉴에 “문구와 격려 설정”이라는 하나의 명확한 진입을 두고 작은 접근 가능한 패널에서 관리한다. 데스크톱·모바일 모두 접근할 수 있어야 한다.
- 문구 설정은 저장/취소가 있는 초안 편집으로 한다. 저장 성공·실패와 닫기/Escape의 의미를 명확히 한다.
- 내 문장은 plain text로 입력하고 앞뒤 공백을 정리한 뒤 1–120자까지 허용한다. 비어 있거나 초과하면 구체적인 오류를 표시한다. 사용자 입력을 HTML로 해석하지 않는다.
- 긴 문구는 줄바꿈하되 320px에서도 넘치지 않도록 한다. 장문의 인용을 강제하거나 글자를 과하게 줄이지 마라.

### 하루 동안의 안정성

- 기기 로컬 날짜를 기준으로 같은 날짜·같은 모드·같은 콘텐츠 버전에서는 새로고침과 재방문 후에도 같은 문구를 보여준다.
- 렌더링마다 Math.random으로 다시 고르지 않는다. 날짜와 문구 id에 기반한 결정적인 선택 등 간단하고 시험 가능한 방식을 사용한다.
- 자정이 지나거나 suspend 후 앱에 돌아오면 현재 날짜로 갱신한다. 네트워크가 없어도 표시된다.
- 사용자가 모드를 바꾸면 그 모드의 오늘 문구로 바뀌며, 원래 모드로 돌아오면 그 모드의 같은 문구가 나온다. 내 문장은 사용자가 저장한 내용이다.
- 유한한 문구 묶음은 시간이 지나 반복될 수 있다. 가능한 범위에서 연속 날짜의 중복을 줄이고 영원히 중복되지 않는다고 주장하지 마라.

### 콘텐츠 품질

- 차분한 문구와 유머 문구를 각각 최소 12개 이상 작성·검토한다. 개수보다 자연스러운 한국어와 반복 없는 내용을 우선한다.
- 예시 방향: “완벽한 하루보다, 시작한 한 가지.” / “작게 시작해도 오늘의 진전입니다.”처럼 짧고 부담 없는 표현.
- 유머는 사용자를 조롱하거나 훈계하지 않고, 미루기·시작·완료 상황에 공감하는 짧은 문구로 작성한다. 욕설·차별·정치·성적 소재·공격적 표현은 넣지 않는다.
- 창작 문구는 Focusday 자체 문구로 구분한다. 유명인의 이름을 임의로 붙이지 않는다.
- 실제 명언이나 유행 밈을 포함한다면 현시점 자료를 확인하고 원문·출처·확인일을 콘텐츠 기록에 남긴다. 출처를 확인할 수 없는 인용은 넣지 않는다.
- 확인하지 않은 창작 문구나 오래된 표현을 “최신 밈”이라고 표시하지 마라. 런타임은 검토된 로컬 콘텐츠만 사용하며, 신뢰할 만한 자료가 없으면 창작 유머로 완성한다.
- 코드에는 안정적인 id와 종류를, 문서에는 인용/창작/밈 참고 여부 및 필요한 출처를 기록한다. 같은 문구를 변형해 개수만 채우지 마라.

## 4. 오늘의 성취 기록 — 집계 의미 확정

새로운 역사 기록 저장소나 완료 이벤트 누적 카운터는 만들지 않는다. 기존 Task.completedAt을 사용해 현재 목록에서 계산한다.

집계 대상은 “현재 데이터에 남아 있는 비예시 항목 중, completedAt을 기기 로컬 날짜로 변환했을 때 오늘인 항목”이다.

- 오늘 보기에서 완료했는지 전체 보기에서 완료했는지와 무관하게 포함한다.
- 기한이나 focusDate가 오늘인지와 관계없이 completedAt의 날짜를 기준으로 한다.
- 예시 항목은 실제 성취 집계에서 제외한다. 기존 전체 완료 목록에서 예시를 볼 수 있는 동작은 유지한다.
- 완료 취소·미완료 복원은 즉시 제외, 삭제는 제외, 삭제 실행 취소로 오늘 완료 항목이 돌아오면 다시 포함한다.
- 합치기/전체 교체가 성공하면 적용된 데이터에서 다시 계산한다. 실패한 복원은 성취 결과도 바꾸지 않는다.
- 새로고침·날짜 변경·다른 시간대에서 보기에도 같은 로컬 날짜 규칙을 사용한다. ISO 문자열의 날짜 앞 10자리로 오늘 여부를 판단하지 마라.
- 검색어는 성취 총개수에 영향을 주지 않는다. 검색 때문에 집계가 줄어드는 일을 막는다.
- 이 수치는 영구 누적 기록이 아니다. 삭제·복원·완료 취소에 따라 바뀌는 현재 목록 기준임을 필요한 도움말에서 짧게 설명한다.

오늘 목록 아래에 기본적으로 접힌 “오늘 마친 일 N개” 영역을 두고, 펼치면 제목·완료 시각·기존 속성을 확인할 수 있게 한다. 현재 디자인의 완료 영역 표현을 재사용하되 오늘 기록과 전체 완료 목록의 범위가 구별되어야 한다.

0개일 때도 실패 표현 없이 간결한 빈 상태를 제공한다. 성취 영역에 숨은 필수 설정을 넣지 않는다. 정렬은 최근 완료 순서 등 일관된 기준을 정하고 기록한다.

해당 영역에서도 미완료 복원을 사용할 수 있게 하되 기존 처리 함수를 재사용한다. 조작으로 행이 사라지거나 영역이 닫힐 때 포커스가 body로 떨어지지 않게 한다. 별도 누적 점수·임의의 달성률·100% 표시를 만들지 마라.

## 5. 완료 순간의 격려 — 중복과 실행 취소

### 발생 조건

- 기본값은 켜짐이며 설정에서 끌 수 있다.
- 위 집계 기준의 실제 사용자 항목을 사용자가 직접 미완료→완료로 바꾸는 순간만 격려 후보로 삼는다.
- 실제 사용자 완료로 오늘 개수가 0→1 또는 2→3이 될 때만 짧은 격려를 표시한다. 하루의 이 두 시점 이외에는 일반 완료 피드백을 유지한다.
- 예시 완료, 초기 로딩, 새로고침, 날짜 변경, 백업 가져오기, 전체 교체, 삭제 실행 취소로 개수가 늘어나는 것은 격려를 발생시키지 않는다.
- 가져온 항목으로 오늘 개수가 2가 된 후 사용자가 실제 새 항목을 완료해 3이 되는 경우는 격려 후보가 된다. 단 같은 날짜의 그 시점을 이미 처리했다면 다시 표시하지 않는다.
- 완료 개수를 state 변경 effect로 관찰해 모든 증가에 축하를 발생시키는 방식을 피한다. 실제 사용자 완료 행동과 계산 전후를 구별한다.

### 중복 방지와 문구

- 같은 로컬 날짜의 “첫 완료”와 “3개 완료”는 각각 한 번만 처리한다. 실행 취소→재완료, 삭제→복원, 새로고침으로 반복 축하하지 않는다.
- 격려가 꺼져 있는 동안 직접 완료로 통과한 시점도 처리된 시점으로 기록한다. 나중에 켜거나 완료를 되돌렸다 다시 완료했다고 소급 축하하지 않는다.
- 한 문장 모드가 끄기/내 문장인 경우 격려에는 차분한 기본 문구를 사용한다. 유머 모드일 때만 검토된 유머 격려를 사용한다. 문구 끄기와 격려 끄기는 독립 설정이다.
- 숫자를 언급한다면 실제 적용된 오늘 개수와 일치해야 한다. 한 일의 양이나 의미를 과장하지 않는다.
- 격려 이력은 날짜·두 시점 수준의 작은 정보만 저장한다. 할 일 제목과 클릭 이력, 사용자 행동 로그를 새로 영구 저장하지 않는다.

### 기존 피드백 보존

- 기존 UndoToast의 완료 안내에 짧게 통합한다. 별도의 두 번째 toast, modal, 전체 화면 축하를 띄우지 않는다.
- 실행 취소·완료 목록·타이머 pause·접근 가능한 상태 안내는 그대로 유지한다.
- 소리·진동·폭죽·계속 반복되는 애니메이션은 넣지 않는다. 필요한 미세 전환도 prefers-reduced-motion을 따른다.
- 빠른 연속 완료에서는 오래된 격려가 나중에 튀어나오거나 undo 대상을 가리지 않아야 한다.
- 완료를 되돌린 뒤에도 “3개 완료”라는 상태 문구가 화면에 남지 않게 한다. 하루의 격려 처리 이력과 현재 성취 집계는 서로 다른 의미다.

## 6. 설정 저장과 백업의 경계

기존 할 일 데이터의 key focusday:v1 / AppData version:1 / 백업 formatVersion:1은 유지한다. 이번 세 기능을 이유로 Task 스키마나 기존 백업 형식을 바꾸지 마라.

- 문구 모드, 내 문장, 격려 켜기/끄기, 날짜별 격려 처리 표시는 별도의 이름과 version을 가진 작은 UI 설정 저장소에 둔다. 기존 할 일 원본과 분리한다.
- v1.3에 설정이 없는 경우 기본값으로 동작하고, 읽기만으로 기존 데이터를 다시 쓰거나 초기화하지 않는다.
- 설정 저장 성공 시에만 저장됐다고 표시한다. 설정 쓰기가 실패하면 초안을 유지하고 재시도를 제공한다. 실패 때문에 할 일 목록이나 기존 저장 상태를 덮어쓰지 않는다.
- 설정의 손상·미지원 버전은 자동으로 덮어쓰지 않는다. 이번 탭에서는 기본값으로 사용하고 설정 영역에서 재시도/명시적 초기화 등 좁은 복구 동작을 제공한다.
- 격려 처리 표시의 저장이 실패해도 실제 완료와 undo는 동작한다. 현재 세션에서는 중복을 막고, 새로고침 이후 중복 방지는 저장 상태에 의존한다는 한계를 기록한다. 완료를 재실행해 저장을 시도하지 마라.
- 기존 JSON 백업은 전체 할 일 속성·완료·예시를 보존한다. UI 설정과 내 문장은 이번 백업 대상에서 제외한다. 백업 설명을 “전체 할 일 백업”처럼 정확히 쓰고, 설정/내 문장은 이 브라우저에만 저장된다는 점을 설정 도움말에 명시한다.
- 과거 v1 백업을 그대로 가져올 수 있어야 한다. 합치기/전체 교체 모두 현재 UI 설정과 격려 처리 이력을 유지하고, 새 성취 개수만 적용된 할 일에서 계산한다.
- 10MiB UTF-8 동일 한도, compact JSON, 중복 id 처리, 미리보기, 교체 확인, 저장 성공 후 적용, 실패 시 원본 보존을 유지한다.

다중 탭 동시 쓰기 해결과 설정의 기기 간 이동은 이번 범위가 아니다. 지원하지 않은 동작을 지원한다고 안내하지 마라.

## 7. 기존 기능과 디자인 보존

- v1.3 DESIGN.md의 노션식 토큰·사이드바·목록 밀도·속성·패널·모바일 sheet를 유지한다.
- 새로운 설정·문구·성취 영역도 기존 타이포그래피와 컨트롤 규칙을 따른다.
- 빠른 입력은 목록 위에 유지한다. Enter 추가 후 빈 입력과 포커스 유지, 공백 오류, 제목 200자, 분류 24자, 조합 Enter 보호를 유지한다.
- 미래 기한+오늘 집중, 오늘/과거 기한+집중 해제 잔류 안내, 어제 수동 이어가기의 id와 기한, 그룹·검색·정렬을 보존한다.
- 편집 초안·저장·취소·Escape·textarea 줄바꿈·삭제·undo와 포커스 복귀를 보존한다.
- 손상 원본 보호·저장 실패 중 메모리 상태·복원 실패·백업 경계 처리를 보존한다.
- 매 실행 날짜가 아닌 제품의 로컬 날짜 처리, 자정·재방문 갱신, 입력/패널 중 단축키 차단을 유지한다.

본문·설정·성취·toast에 대해 1440×900, 1366×768, 1024×768, 768×1024, 390×844, 320×568, 작은 높이와 reflow를 확인한다. 터치 대상 약44×44px, 필수 조작 항상 접근, 명확한 포커스, modal 닫기 후 복귀, 대비, 긴 한글/영문, 키보드와 화면 하단 겹침을 검수한다. 기능 때문에 기존 제목·입력·첫 항목을 과하게 아래로 밀지 않는다.

## 8. Synthetic Beta — 가상 사용자 12개 관점

AI가 만든 가상 사용자 관점과 실제 브라우저/코드 실행 근거를 결합한다. 가상 사용자를 실제로 모집한 사람처럼 표현하지 마라. 사용자 이름·감정·만족도·실제 과업 시간을 만들어 조사 결과로 쓰지 않는다.

각 관점은 서로 다른 조건·과업·확인 기준을 가져야 한다. “좋아했습니다” 같은 생성된 소감만으로 PASS 판정을 내리지 않는다.

| ID | 관점 | 중점 |
| --- | --- | --- |
| P01 | 처음 사용하는 사용자 | 빈 앱, 첫 입력, 설명·설정·성취 발견 |
| P02 | 키보드 중심 사용자 | Enter·Tab·Escape, 입력/검색/패널/복원 포커스 |
| P03 | 한글 입력 사용자 | 조합 Enter, 연속 입력, 내 문장·분류·제목 편집 |
| P04 | 모바일 터치 사용자 | 390px, 조작 영역, 하단 nav·toast·sheet |
| P05 | 작은 화면 사용자 | 320px, 작은 높이, 긴 문구·제목·분류 |
| P06 | 쌓인 일이 많은 사용자 | 목록·검색·정렬·계획 후보, 실제 정보 보존 |
| P07 | 계획을 자주 바꾸는 사용자 | 집중과 기한, 어제 이어가기, 취소·재선택 |
| P08 | 실수가 잦은 사용자 | 완료·삭제·undo·재완료, 집계와 중복 격려 |
| P09 | 격려를 선호하는 사용자 | 하루 문구, 첫/3개 완료, 모드 변경·재방문 |
| P10 | 조용한 화면을 선호하는 사용자 | 문구·격려 끄기, 설정 저장·취소·유지 |
| P11 | 확대·낮은 시력을 고려한 관점 | 대비·200%/reflow·키보드 접근·긴 정보 |
| P12 | 날짜·데이터 보존에 민감한 사용자 | 자정·시간대·백업·복원·설정/할 일 저장 실패 |

각 관점에 “입력 → 계획 → 완료 → 실수 복구 → 설정/백업 → 재방문”의 연결된 시나리오를 설계하고 실제 실행한다. 관점별 필요한 단계만 구성하되 모든 관점에 똑같은 시나리오를 복사하지 않는다.

여러 날짜의 사용은 테스트 시계와 격리 context로 최소 두 개의 가상 날짜 및 재방문 세션을 재현한다. 실제로 며칠 사람이 사용한 시험이라고 표현하지 마라. 자동화 완료·초점·스크롤·계산·저장·오류·실제 캡처를 근거로 삼고, 생성된 사용자 해석은 설계 가설로 구별한다.

가상 관점 검토를 지원하는 도구가 있으면 독립된 역할로 검토할 수 있지만, 브라우저 실행 근거 없는 역할 응답은 합격 증거로 취급하지 않는다. 사람이 쓰는 실제 목록과 데이터는 변경하지 않는다. 서로 다른 관점의 fixture와 설정은 격리한다.

## 9. 반드시 포함할 검증 시나리오

### 문구·설정

- 같은 날 refresh/reopen에서 동일, 다른 날 갱신, 모드 왕복, 자정·suspend 후 재방문, 네트워크 없이 표시
- 내 문장 공백/120자/121자/긴 한글/HTML 같은 문자열, 저장·취소·Escape
- 문구 끄기·격려 끄기 독립, 설정 재방문 유지, 설정 저장 실패·손상·미지원 버전 보호
- 콘텐츠 id/종류/중복·출처 구분과 표현 품질 확인

### 성취·격려

- 0→1, 1→2, 2→3, 3→4의 정확한 집계와 표시 여부
- 전체에서 완료한 일, 집중/기한 없는 완료, 어제 완료, 예시 완료, 검색 중 완료
- undo→재완료, 미완료 복원→재완료, 삭제→undo, 날짜 변경
- 같은 날 새로고침 후 첫/3개 시점 중복 방지, 격려 끄기 동안 통과한 시점의 소급 방지
- import/replace/초기 로드가 격려를 만들지 않음, 복원 후 직접 완료 경계
- 빠른 연속 완료와 최신 undo 대상, 완료 취소 후 오래된 수치가 남지 않음
- 서울/뉴욕의 자정 경계와 UTC 날짜가 다른 완료 timestamp
- 성공한 복원 뒤 개수 재계산, 실패한 복원 뒤 데이터·개수 보존
- 성취 영역 복원 후 focus 관리, 0개/긴 목록/긴 제목

### 기존 회귀

- 빠른 Enter 입력·공백·긴 제목·조합 입력, 오늘/전체·검색·완료·정렬
- 기한/집중 분리, 어제 이어가기, 상세 편집 초안·취소·줄바꿈
- undo pause·초점 복귀, 저장 보호·실패, 10MiB 백업 경계와 자체 백업 재가져오기
- 320px 패널·모바일·keyboard-only·reflow, /focusday/ production 경로

기존 테스트를 유지하고 새 기능의 경계·부작용에 필요한 시험을 추가한다. 테스트 수를 채우려고 같은 assertion을 복제하지 않는다. 새 디자인으로 locator가 바뀌면 의미와 기존 검증 강도를 유지해 수정한다. 테스트 삭제·skip·완화로 통과를 만들지 마라.

## 10. 발견 문제의 수정과 최종 검수

새 기능 구현 후 첫 Synthetic Beta 결과를 기록한 뒤 수정한다. 기록 없이 모든 시나리오를 처음부터 PASS였다고 정리하지 마라. 실제 첫 실행에 문제가 없었다면 그것도 사실대로 기록한다.

발견 항목은 데이터 손실·오작동 → 입력/복구/접근 불가 → 정보·문구 이해와 시각적 불편 순서로 해결한다. 버그마다 재현 단계, 기대/실제, 원인, 수정, 재검증 근거를 연결한다. 과거 데이터와 위험한 오류를 우선한다.

작은 불편도 범위 안에서 직접 수정한다. 수정 중 새 기능을 더 붙이지 않는다. 치명적·중대한 미해결 문제가 있으면 최종 완료나 배포 성공이라고 발표하지 마라.

검사 상태는 PASS / FAIL / NOT_RUN / INCONCLUSIVE로 구분하고 관찰 결과에 맞게 사용한다. 실행하지 못한 것은 FAIL이나 PASS로 임의 처리하지 않는다. 기존 v1.3 검증 범위에서 물리 스마트폰·실제 가상 키보드·OS IME·native zoom·스크린 리더·Safari/Firefox 등은 미실행이었음을 이해하고, 이번에 실제 실행한 경우에만 범위를 확장한다.

브라우저 에뮬레이션·합성 composition·축소 viewport를 실제 기기·OS 한글 입력·native 확대·사람 사용자 연구로 기록하지 마라. 실제 사용자 만족도·사람의 완료 시간·통계적 UX 개선을 주장하지 않는다.

수정한 시나리오를 재실행하고, 최종 코드에 대해 pnpm check와 전체 E2E를 다시 실행한다. 루트 production과 Pages /focusday/ 빌드·자산·동작을 확인한다. 패키지 명령과 서버 재사용 방식은 실제 프로젝트 설정을 따른다.

## 12. GitHub·배포·완료 기준

필요한 검증과 문서화가 완료되면 기존 제출 방식에 맞춰 정상 커밋·push한다. 원격 사용자 변경을 덮지 않고, PR/보호 규칙 등 실제 저장소 정책을 따른다. 기존 Pages 배포 workflow를 사용해 공개 사이트를 갱신한다. 확인 당시 Pages는 main 수동 workflow이므로 push만으로 배포됐다고 보고하지 마라.

배포 후 공개 버전1.4.0·자산·desktop/mobile 기본 조작·문구/설정·성취/undo·백업을 격리 context에서 다시 확인하고 실제 결과를 기록한다. 공개 검증에서 문제를 찾으면 수정하고 다시 배포·확인한다. 권한·검토 정책·환경이 막히면 우회하지 말고 로컬 구현과 검증은 끝까지 완료한 뒤 미완료된 원격 단계만 정확히 보고한다.

이번 요청은 v1.4를 최종 제출 버전으로 마무리하는 작업이다. 세 기능 외 확장 아이디어를 추가하지 않는다. 정상 작동·명확한 의미·노션 UI 일관성·검증 근거·제출 문서가 갖춰지면 작업을 마친다.

1. 세 기능과 최종 수정의 실제 결과
2. 가상 사용자 평가와 실제 실행 근거의 구분, 최초/최종 검사 결과
3. 기존 데이터·백업 호환과 새 UI 설정의 저장/백업 범위
