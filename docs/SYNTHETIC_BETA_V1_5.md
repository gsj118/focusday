# Focusday v1.5 · 가상 사용자 직접 체험

> **후속 정정:** 아래 교수 시나리오에서 새 오늘 기한이 계획 밖에 남아도 기존 3개 완료 후 종료되는 동작을 정상으로 판단했다. 사용자 제보를 통해 이 판단이 잘못됐음을 확인했다. 새 오늘 기한 자동 포함과 종료 안내 조건을 수정했으며 [최신 재현·검증](validation.md)에 기록했다. 아래 수치와 원본 관찰은 해당 수정 전 기록이다.

2026-11-20 KST. 같은 에이전트가 네 가지 사용 습관을 가정하고 실제 로컬 앱을 조작했다. 별도 사람이나 하위 에이전트를 모집한 결과가 아니다. 이름·사용 성향은 시험을 위한 설정이며 만족도·인터뷰·사람의 과업 시간은 만들지 않았다.

**추가 연결 검수:** 사용자 재검수 요청으로 메모 작성 중 자정 경과, 편집 중 다음 날 계획 갱신, 다음 날 완료·삭제·추가 취소를 이어서 실행했다. 미리보기의 날짜 확인 누락·한글 조합 저장, 편집 체크 상태, 지난 계획의 무효 취소, 기존 기한 변경의 계획 누락 등 다섯 문제를 수정했다. 후속 브라우저 시나리오 16개와 전체 139개가 통과했다. [최신 상세 기록과 한계](validation.md) · [실제 조작 관찰](evidence/v1.5/lifecycle-ui.json). 아래 표와 최초 수치는 이전 검수 당시 기록이다.

## 사용한 페르소나와 관찰

| 가상 사용자                                           | 목표와 실제로 한 행동                                                                      | 관찰                                                                                                                                                                                        |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 서연 · 과제를 빠르게 살펴보는 교수                    | 체험 첫 방문 → 예시 메모 정리 → 3개 저장 → 오늘의 3개 완료                                 | 새 메모가 전체 목록에 들어가도 오늘 분량은 유지됐다. 3/3에서 종료했고 계획 밖의 오늘 기한은 별도로 표시했다.                                                                                |
| 민준 · 정리를 귀찮아하는 학생                         | 예시를 쓰지 않고 생활 메모 입력 → 직접 줄 나누기 → 처음 4개 저장 → 새로고침                | ‘제출하고 우유 사기’가 한 항목으로 남았고, 반복 문장의 요일이 사라졌다. 첫 저장은 실제로 3개 계획을 만들지만 안내는 기존 분량이 유지된다고 했다. 저장·재방문은 정상이며 세 문제를 수정했다. |
| 지우 · 계획을 자주 바꾸고 실수를 바로 되돌리는 사용자 | 분량 3→1→되돌리기, 제목 편집 취소, 제목 저장→되돌리기, 삭제→되돌리기, 나중에 하기→되돌리기 | 각 변경을 복구했고 제목·기한·오늘 목록도 유지됐다. 새로고침 후 최근 작업 이력이 사라지는 기존 범위도 확인했다.                                                                              |
| 하린 · 작은 화면을 쓰는 사용자                        | 390×620에서 잘못된 날짜 입력 → 자동 정리 끄기 → 원문 2개 저장 → 되돌리기 → 예시 버튼       | 잘못된 날짜는 전체 저장을 보류하고 원문을 유지했다. 원문 저장·복구도 됐다. 그러나 예시 버튼이 작성 중 메모를 덮어쓰는 문제를 발견해 수정했다.                                               |

실제 개인 목록과 분리하려고 별도 로컬 주소 `http://127.0.0.1:4191/`를 사용했다. 교수 역할은 메모리 체험이며, 학생·계획 변경·모바일 역할은 직접 만든 동일 시험 목록을 이어서 사용했다. 데스크톱 1366×768, 모바일 상당 390×620 조건이다. 물리 스마트폰이나 실제 가상 키보드 검증은 아니다.

## 발견한 문제와 수정

| 문제                                  | 수정한 동작                                                                                                                                 | 확인할 반례                                                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 여러 행동이 한 항목에 남음            | ‘제출하고’, ‘정리하고’, ‘돌리고’ 등 지원하는 행동 연결은 분리한다. 같은 문장 첫머리의 날짜를 다음 항목에도 적용했으면 확인 안내를 표시한다. | ‘친구하고’, ‘사고’, ‘공부하고 싶은’은 나누지 않는다. 다른 명시적 날짜를 덮어쓰거나 다음 문장·줄로 날짜를 옮기지 않는다. |
| 반복 미지원 안내와 달리 요일이 사라짐 | ‘매주 금요일 운동’의 반복·날짜 표현을 제목에 보존하고 기한은 비워 둔다. 이번에 할 기한은 직접 선택하도록 안내한다.                          | ‘매일경제’, ‘반복문’ 같은 단어를 반복 일정으로 취급하지 않는다. 반복 문장을 나눠 반복 맥락을 잃지 않는다.               |
| 처음 저장할 때 안내와 동작이 다름     | 아직 계획이 없으면 ‘이 중에서 오늘 할 분량을 자동으로 골라요’라고 설명한다. 기존 계획이 있으면 분량 유지 안내를 보여준다.                   | 자동 계획을 끈 경우와 이미 정한 계획의 안내는 각각 유지한다.                                                            |
| 예시 버튼이 작성 중 메모를 덮어씀     | 내용이 있으면 ‘예시 덧붙이기’로 표시하고 원문 뒤에 추가한다. 길이 제한을 넘으면 원문을 바꾸지 않는다.                                       | 줄바꿈·끝 공백을 포함한 원문 보존, 빈 입력에서 기존 예시 동작, 24,000자 경계.                                           |

입력 사례는 실제로 다음과 같이 사용했다.

```text
내일 과제 제출하고 우유 사기
다음 주 월요일 발표 준비
매주 금요일 운동 30분
```

수정 후 기대 결과는 ‘과제 제출하기’와 ‘우유 사기’의 기한이 내일, ‘발표 준비’가 다음 주 월요일, ‘매주 금요일 운동 30분’은 제목 그대로·기한 없음이다. 반복 일정이나 시간 알림을 새로 구현한 것은 아니다.

## 남은 판단

완료 후 다음 행동, 정한 분량의 종료, 최근 변경 복구는 이 시나리오에서 이어졌다. 자동 정리의 범위는 지원하는 한국어 규칙까지다. 임의의 복잡한 문장을 모두 이해하거나 반복·시간 알림을 만드는 기능으로 안내하지 않는다. 인식되지 않은 연결 표현은 한 항목에 남을 수 있어 미리보기 수정·줄바꿈·원문 모드를 유지한다.

같은 기한의 ‘우유 사기’와 ‘과제 제출’ 사이에서 과제가 더 중요하다고 의미를 추론하지는 않는다. 이 체험에서도 우유가 먼저 표시됐으며, 중요도는 지원하는 우선순위 표현이나 직접 수정으로 구분해야 한다. 추천 순서는 제품 명세의 기한·선택·우선순위·생성 시각·id 규칙을 따른다.

버튼을 실제로 찾고 과업을 수행한 결과와, 인간이 편리하다고 느끼는지는 구분한다. 사람이 설명 없이 같은 과업을 수행하는 관찰은 아직 하지 않았다.
